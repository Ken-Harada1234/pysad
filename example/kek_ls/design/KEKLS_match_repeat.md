# KEKLS_match_repeat
種別: 診断 (modules_cell_match.n の再現性)。フォルダ: `design`。元のスクリプト: (元の台本には無い。tune_survey_cell の確認のために足した)。ラティス: `../lattice/kek_ls_v03_68.sad` (3 GeV、周長 570.72 m、標準セル 20 個)。フラグ: `ON RAD FLUC COD RFSW RADCOD`。

## 何を見る例か
同じセルのマッチング (`InitMag[]` → `MatchingARCA[1]` ×2 → `MatchingARCA[0.001]` → `ChromCor[]`) を 3 回繰り返し、毎回同じ結果になるかを見る。

## スクリプト
`KEKLS_match_repeat.sad` (先頭に `../lattice/kek_ls_v03_68.sad` を貼った自己完結のファイル。台本の本体は `FFS;` から。説明のコメントは台本の先頭にある)。共通モジュールは `Get["../modules/..."]` で読む (台本のあるフォルダをカレントにして走らせる)。

## gs と pysad の比較
判定: **○** (比べた行 12、最大の相対差 2.7e-05、k64 モードの pysad)。3 回とも同じ値で gs と同じ (A: QFA1H 0.5115137183 / gs 0.5115137397、リングのチューン 48.58012266 / 48.58012266)。残りの差は FitFunction の片側差分の数値雑音。

所要時間: gs 1 秒、pysad 20 秒 (この PC。k64 モード)。

## 未確認・限界
- gs と pysad の FIT の挙動の違いに効く点 (docs/31 §4): (1) `FFS["fit MKSFA1 BX 3."]` の末尾の数 `3.` を読み落とさないこと、(2) gs の tfsolv は FitFunction の行を不等式型 (最初は解から外す) として扱う (k64)、(3) gs は USE のたびに DP を MARK の値に戻す (ChromCor の `DP = 0;` の持ち越しで 2 回目以降が変わらないようにする)。
- 元の台本 (matching2_01 の `FitFunction` が NaN のとき pysad が動かない) と同じ現象かは確認していない。
