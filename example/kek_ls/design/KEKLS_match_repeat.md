# KEKLS_match_repeat
種別: 診断 (modules_cell_match.n の再現性)。フォルダ: `design`。元のスクリプト: (元の台本には無い。tune_survey_cell の確認のために足した)。ラティス: `../lattice/kek_ls_v03_68.sad` (3 GeV、周長 570.72 m、標準セル 20 個)。フラグ: `ON RAD FLUC COD RFSW RADCOD`。

## 何を見る例か
同じセルのマッチング (`InitMag[]` → `MatchingARCA[1]` ×2 → `MatchingARCA[0.001]` → `ChromCor[]`) を 3 回繰り返し、毎回同じ結果になるかを見る。

## スクリプト
`KEKLS_match_repeat.sad` (先頭に `../lattice/kek_ls_v03_68.sad` を貼った自己完結のファイル。台本の本体は `FFS;` から。説明のコメントは台本の先頭にある)。共通モジュールは `Get["../modules/..."]` で読む (台本のあるフォルダをカレントにして走らせる)。

## gs と pysad の比較
判定: **△** (比べた行 12、最大の相対差 5.7e-02、k64 モードの pysad)。(再現性の診断。pysad は 1 回目と 2 回目以降で値が違う (A の QFA1H: 0.5198 → 0.5201 → 0.5201。gs は 0.51151 を 3 回)。さらに、gs と pysad の最初のマッチングの結果も違う (A のリングのチューン gs 48.58012、pysad 48.5909 (収束していない))。FitFunction (6 極の対の位相条件) を fit 条件と同時に使う `MatchingARCA` での FIT の扱いの差の疑い。pysad のコードは変えていない)。

所要時間: gs 1 秒、pysad 20 秒 (この PC。k64 モード)。

## 未確認・限界
- 原因は未確認 (pysad の FIT 状態の持ち越し、または FitFunction の重みの扱い)。`KEKLS_tune_survey_cell`・`KEKLS_scan_target` の gs と pysad の違いはこれが原因とみられる。
- 元の台本 (matching2_01 の `FitFunction` が NaN のとき pysad が動かない) と同じ現象の疑いがある。
