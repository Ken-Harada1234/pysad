# KEKLS_match_chrom
種別: FFS の `fit`、`FITP`、6 極のクロマティシティ補正。フォルダ: `design`。元のスクリプト: matching2_01 (後半)。ラティス: `../lattice/kek_ls_v03_68.sad` (3 GeV、周長 570.72 m、標準セル 20 個)。フラグ: `ON RAD FLUC COD RFSW RADCOD`。

## 何を見る例か
リング `RINGC` の6 極 `SDH`・`SFH` の K2 で、チューンを保ちつつ運動量 DP = 0.001 でも同じチューンにする (クロマティシティを 0 にする) マッチング。ξ を `DP0 = ±0.0005` の差分で前後に表示する。

## スクリプト
`KEKLS_match_chrom.sad` (先頭に `../lattice/kek_ls_v03_68.sad` を貼った自己完結のファイル。台本の本体は `FFS;` から。説明のコメントは台本の先頭にある)。

## 結果の読み方
`FIT; NX nx0 4; NY ny0 4; SD* MAX 0; SF* MIN 0; DP=0.001; FREE SD*,SF*; GO; FITP 1;`。before の ξ (+0.119, −0.684) が after で (≈ 0, ≈ 0) になる。K2 の変化は SDH −12.382 → −12.437、SFH 15.134 → 15.150。

gs の出力の抜粋 (指定の行だけ。全体は `KEKLS_match_chrom.gs.txt`):
```

before: K2 SDH  -12.3824864079  SFH   15.1343981068

after : K2 SDH  -12.4367982768  SFH   15.1500612041
```

## gs と pysad の比較
判定: **△** (比べた行 4、最大の相対差 3.0e-01、k64 モードの pysad)。before は全桁一致。after は ξ が gs (−0.0051, −0.0065)・pysad (−0.0073, −0.0070) で、どちらも 0 に近いが違う (目標からの残りがほぼ同じ大きさ、K2 が 2e-4 違う)。

所要時間: gs 1 秒、pysad 9 秒 (この PC。k64 モード)。

## 未確認・限界
- 元の台本は前半のセル調整に続けて走る。ここは設計値の RINGC から単独で始める (整理前の前半からの連続の結果とは比べていない)。
- 追跡 (DAsv) は含めない (`modules/modules_general.n` の `DAsv[]`。`DAturns` を小さくして使える)。
