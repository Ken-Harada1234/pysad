# flag_ABSW_RELW (ABSW と RELW)
種別: フラグ。フォルダ: 03_matching。ラティス: `00_lattice/FODO_ring.sad`。エネルギー 3 GeV。フラグ: CELL。

## 何を見る例か
`ABSW` (既定): マッチングの変数の重みを値によらず一定にする。`RELW` (反意語): 重みを変数の値に**比例**させる (値の大きい変数ほど動きにくい、または動きやすくなる)。2 変数 2 条件で厳密に解ける問題では重みは解に効かないので、**解のない目標** (NX=0.2、NY=0.2) で、収束せずに止まる点の違いを見る (flag_UNIPOL_BIPOL の B と同じ設定)。

## スクリプト
```
FREE QF QD;   FIT $$$;   NX 0.2 NY 0.2;   GO;       ! ABSW
QF K1 0.7; QD K1 -0.6;   RELW;   GO;               ! RELW
```

## 結果の読み方 (K1 の QF, QD)
| | gs | pysad |
|---|---|---|
| ABSW | (-0.005524, -0.005792) → NX,NY = (1.42, 1.299) | (-0.008547, -0.008878) → (1.275, 1.443) |
| RELW | (-0.005465, -0.00585) → (1.42, 1.299) | (-0.008547, -0.008878) → (1.275, 1.443) |

## 物理・解析式
なし (最適化の重みの定義。解析解のある問題では重みは効かない)。

## gs と pysad の比較
- gs では ABSW と RELW で止まる点が違う ((-0.005524, -0.005792) と (-0.005465, -0.005850))、つまりフラグが効いている。
- pysad は ABSW と RELW で**同じ結果**になり (RELW が効いていない)、gs の RELW とも ABSW とも違う。docs/35 では RELW を `ffscmd.matcher_` で `match6` の重みにつないだとあるが、この収束しない問題では効きが見えない。
- 収束しない問題での比較なので、不一致の意味は小さい (flag_UNIPOL_BIPOL の B BIPOL と同じ状況)。収束する問題では重みは効かないので、ABSW/RELW を意味のある条件で比べる例は作れなかった。

## 未確認・限界
- 3 変数以上で冗長な (条件より変数が多い) マッチングでの ABSW/RELW の差は未確認 (FFS_REJECT のように最小ノルムを選ぶ場面で重みが効くはず)。
