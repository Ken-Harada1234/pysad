# fn_FitValue_FitWeight_VariableRange_VariableWeight (マッチングのフック関数)
種別: SADScript の関数 (ユーザー定義のフック)。フォルダ: 03_matching。ラティス: `00_lattice/FODO_ring.sad`。エネルギー 3 GeV。フラグ: CELL。

## 何を見る例か
`GO` の内部で呼ばれる、ユーザーが定義できる関数 (`:=` で定義する):

| 関数 | 役割 |
|---|---|
| `FitValue[位置, 関数, {id_, dp_}, goal_, now_] := 式` | 目標値を式の値に置き換える |
| `FitWeight[位置, 関数, {id_, dp_}, w_] := 式` | 条件の重みを置き換える |
| `VariableRange["要素", "キーワード", v_] := {min, max}` | 変数の範囲を狭める (実数なら限界値) |
| `VariableWeight["要素", "キーワード", v_] := 式` | 変数の重みを置き換える (実数以外なら既定) |

## スクリプト
```
FitValue["$$$", "NX", {_, dp_}, goal_, now_] := goal + 0.05*2*Pi;        ! NX の目標を 6.75 に
FitWeight["$$$", "NY", {_, dp_}, w_] := 100*w;
VariableRange["QD", "K1", v_] := {-0.58, 0};
VariableWeight["QF", "K1", v_] := 0.1*v;
```
(各例のあとには、同じ関数を恒等の定義 `... := goal;` に戻した。フックの定義は一度書くと残るため。)

| VariableWeight | (0.700221, -0.599636) | (0.700221, -0.599636) | 解は plain と同じ |

## 物理・解析式
2 変数 2 条件で厳密に解ける場合の解は、重み (FitWeight・VariableWeight) に依らない。FODO リングの 2x2 行列の模型で解くと:
| ケース | 式の値 (QF, QD) | gs | pysad |
|---|---|---|---|
| plain (6.7, 4.9) | (0.700221, -0.599636) | (0.700221, -0.599636) | (0.700221, -0.599636) |
| FitValue (6.75, 4.9) | (0.704275, -0.600589) | (0.704275, -0.600589) | (0.704275, -0.600589) |
| VariableRange: QD=-0.58 での NX, NY | (6.6255, 4.6452) | (6.6255, 4.6452) | (6.6255, 4.6452) |

(`VariableRange` の行は、QD を -0.58 に固定し QF を gs の値にしたときのチューン。範囲に阻まれて目標に届かない解の値が模型と一致する。)

## gs と pysad の比較
**K1・チューンは全ケースで一致。** 違いは `Matched`/`Residual` の表示だけ: FitValue を定義した状態の `GO` で、gs の残差は書き換えた目標に対するもの (`Matched. ( 8.8E-18 )`) だが、pysad は元の目標 (6.7) に対する残差 (`Residual = 2.079`) を表示する。FitWeight の残差の表示値も違う (gs `5.4E-21`、pysad `2.069`)。解は同じなので △ (表示のみ)。

## 未確認・限界
- FitWeight/VariableWeight は、厳密に解ける問題では解を変えないので、効きを確かめていない (重みが効くのは条件が矛盾・冗長なとき)。
- `FitValue` の 2 点条件の形 (`FitValue[c1,c2,fn,{id,dp},goal,now1,now2]`) と、`dp_` を使ったオフモメンタムの目標 (SADHelp の例: `goal + dp*xix*2*Pi`) は未確認。
