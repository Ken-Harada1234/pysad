fn PolynomialFit (PF): チューンの運動量依存を多項式で当てはめる

種別: 関数 + 特殊変数 DP0 (サンプル集 calc_chromaticity と、KEK の SAD チュートリアルの話題をもとにした)。加速器: PF 2.5 GeV リング (lattice/v9_16_asym.sad、周長 187.035 m、チューン 9.5975 / 5.2790)。

何を見る例か

DP0 (設計運動量からのずれ) を -2%〜+2% に 0.1% 刻みで 41 点動かし、チューンを Table[] のリストに入れて PolynomialFit[リスト, 次数] で当てはめる。 PolynomialFit は {{c0, c1, c2, c3}, {Residual -> r}} を返す ($\nu = c_0 + c_1\delta + c_2\delta^2 + c_3\delta^3$)。

スクリプト

tunex = Table[{0,0},{41}];
Do[ DP0 = (i-21)*0.001;  FFS["cell calc"];  tunex[i] = {DP0, Twiss["NX","$$$"]/2/Pi}; ...,{i,1,41,1}];
DP0 = 0;   Print[PolynomialFit[tunex,3]];

Do[] の中でコマンドを使うときは FFS["cell calc"] と包む。DP0 = 0; に戻し忘れると以後の計算が狂う。

結果の読み方

  • チューンは δ=0 の近くで極値 (6 極補正済みなので ξ≈0)、δ が大きいと高次の依存が見える。
  • 対称な範囲 (平均 0) の当てはめでは、最高次以外の係数が壊れる (SAD の Packages/Fit.n の癖。pysad の docs/05_sadscript.md にも同じ記述。gs も pysad も同じ値を出す)。 下の表のように、-2%〜+2% の 3 次当てはめは c3 (νx 257.84、νy 1049.07) だけが numpy と一致し、c0〜c2 は別の値 (c0 = 355.6 は明らかに誤り) になる。平均が 0 でない範囲 (-2%〜+1%、31 点) では全係数が numpy と一致する。

物理・解析式

$\xi = d\nu/d\delta$ ($\delta = \Delta p/p$) は c1。次数が高いほど広い範囲を追えるが、範囲の端で振動する。表の「numpy」は、gs が出した点を numpy.polyfit で当てはめた検算。

gs と pysad の比較

v2 モードと k64 モード: .pysad.txt は既定の v2 モードの出力。v2 は K64 のバグを含まない計算なので (docs/28_v2_vs_k64.md。主に Emittance[]・EMIT・追跡の Jx の端の項 B75 と MomentumCompaction B77)、この例の出力のうち Emittance[] の表示 (εx が数 % 大きい、εz・減衰率・α・バケット高さなど) と、それに依る量が gs と違う。以下の「一致」の判定は k64 モードの結果。gs と同じ値が要るときは PYSAD_COMPAT=k64 を付ける。 PolynomialFit の係数は v2 では gs と意図して違う (B18): x の平均が 0 のデータ (-2%〜+2% の 3 次当てはめ) で K64 は係数を誤る (c0 = 355.6 など)。v2 は numpy と同じ真の係数を返す (νx: c0〜c3 = 9.5974680739、.0265778640、88.1362042756、257.8402260944。νy: 5.2798106315、-.0802612065、-87.8828991332、1049.072115306。Residual は同じ)。gs の壊れた値は PYSAD_COMPAT=k64 で再現し、上の「壊れる癖も同じ」はこの k64 モードの結果。平均が 0 でない範囲 (-2%〜+1%) は両モードとも gs と同じ。

○ 41 点のチューンは全桁一致、係数は 10 桁一致 (壊れる癖も同じ)。
