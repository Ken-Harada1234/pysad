# v07_14: チューンのマッチング・チューンサーベイ・誤差の計算 (補正しながら誤差を大きくする手法) の一式

> **注意 (6 極の値について)**: この例のラティス台本 (`v07_14_*.sad`) に入っている 6 極の値と、ここで「完成版」と呼ぶ有効な 6 極のセットは、**論文用の最終版ではない**。設計の途中の版であり、この例は 6 極の最適化の手順を示すためのものである。ここで出した DA・LMA などの数値は、この簡略な設定での比較で、論文や最終設計の値としては使わないこと。

DDBA 型ハイブリッドリングの最終の版 v07_14 (周長 749.48 m、30 セル、5 GeV と 2.5 GeV) について、設計のスクリプト (チューンのマッチング、6 極の色収差補正)、チューンサーベイ、誤差の計算 (**誤差を段階的に大きくしながら、各段階で COD を補正していく手法**)、パラメータ表示を、元の SAD スクリプト群から読み解いて、一式の例にしたものです。gs (SAD K64) と pysad (k64 モード) で走らせて比べてあります。

- 元のスクリプトとの対応、変更点、元の設定と例の設定: [`ORIGINAL_MAP.md`](ORIGINAL_MAP.md)
- 6 極の最適化の検証・代替の検討 (別の担当): [`sextupole/`](sextupole)
- DDBA の 28 のラティスの一覧: [`../README.md`](../README.md)

**関連する公開論文** (6 極の設定について): K. Harada et al., "Conceptual design of the Hybrid Ring with superconducting linac", J. Synchrotron Rad. 29, 118–124 (2022), DOI 10.1107/S1600577521012753。この論文は 3 GeV・周長 350 m・16 セルの暫定設計で、v07_14 (5 GeV・2.5 GeV、周長 749.48 m、30 セル) とは別の版です。論文には6 極の K2 の値や最適化の手法の記述はなく、「6 極の最適化で、入射に必要な水平アパーチャを、通常の 16 回対称 DDBA リングの約 80% まで回復した」という記述だけがあります。**この例の6 極 (最終設定、20231205 の再調整版) は、pysad の作者とは別の研究者 (この論文の著者の一人) の手による最適化の結果**で、論文の設定と一致する、同じ最適化の結果である、という意味ではありません。

## 2. 全体の流れ

```
ラティス (lattice/)
   │
   ├─ design/V0714_match_tune     チューンのマッチング: 2 セルの単位 (TCELLA・TCELL) のセルチューン = リングのチューン/15 に、
   │                              四極・偏向磁石の K1 で合わせる → セルごとの6 極 S3・S4 の色収差補正 → リングの δ スキャン・R56
   ├─ design/V0714_chrom_cell     6 極の色収差補正 (S1・S2 = 0 で S3・S4 だけ。設計の道具)

   │
   ├─ errors/V0714_correct_cod    誤差の計算: 誤差 (位置ずれ・強さ・回転) を与え、位置ずれを段階的に大きくしながら、
   │  errors/..._2.5GeV           各段階で COD を補正 → 補正後のチューン・COD・分散のずれ・動的口径
   │
   └─ display/                    パラメータ表示: V0714_ring_params (光学・ジオメトリ)、V0714_radint (放射積分)、

```

設計の流れ (マッチング → 6 極の補正) は、ラティスの値を決め直す道具で、v07_14 のラティスはその結果をすでに持つ。例の台本は、設計値から出発して、意図的に崩した偏向角を戻す (`V0714_match_tune`)、または設計のチューンの周りの格子を振る (`V0714_tune_survey`) 形にした。**6 極の最終設定は、このマッチングの出力ではない** (6 極は別のソフトで別の研究者が最適化した結果で、`V0714_match_tune` の6 極の補正 (S3・S4 の色収差補正) は設計の出発点と同じ種類の道具)。

## 4. 誤差の計算の手法: 補正しながら誤差を大きくしていく (`errors/V0714_correct_cod`)

元の台本名の `grad_res` は gradual (段階的に) ... のように読めるが、台本に説明はない。台本の中身から読み取ると、**位置ずれの大きさを 1/5、2/5、…、全部 の 5 段階で段階的に大きくし、各段階で COD の補正を繰り返して、補正した状態 (補正磁石の K0) を次の段階に引き継ぐ**手法である。

### 4.1 手順 (1 つの乱数の種ごと。フロー)

```
 設計の光学 (誤差なし)
   │  tunex・tuney、PM・HD・VD でのツイス、設計の分散 (etaideal*) を取る
   │  COD 応答行列 Responsex[j, i] = 0.5 √(βm βc) cos(πν − |φm − φc|) / sin(πν)   (設計のツイスの解析式。補正磁石 j・モニター i)
   ▼
 種 k (SeedRandom[187] から作った 1000 個の表の k 番目) で誤差を与える
   │  位置ずれ DX・DY: B*・Q*・S*・補正磁石 H*・V* に、ガウス分布 (σ = ae、±1σ で打ち切り GCUT = 1)
   │  強さの誤差 DK: B*・Q*・S* に σ = fe = 5e-4 (相対)
   │  回転 DTHETA: B*・Q*・S* に σ = te = 1e-4 rad
   │  ・位置ずれの全体 (aexall0・aeyall0) を覚える
   ▼
 段階 j = 1 … 5   位置ずれ = 全体 × j/5   (DK・DTHETA は初めから全部)
   │
   │   補正の繰り返し (段階 1〜4: nitr 回、最後の段階: nitrlast 回)
   │     ① cell calc。全モニター PM* の COD (befx・befy) を読む
   │     ② CodCorr: (応答行列 × 応答行列の転置) の固有値分解 → 大きい方から ICX/2 個 (= 120 個) の固有値だけで逆行列 → kick
   │     ③ 補正磁石 HD*・VD* の K0 を  K0 ← K0 − ゲイン × kick  (ゲイン 0.5。元は 4 段階目だけ 0.6)
   │     ④ cell calc。補正後の COD の rms と、チューンを表示
   │
   │   K0 は次の段階に引き継ぐ (0 に戻さない)
   ▼
 補正後のチューンが窓 (47.5〜48、16.5〜17) に入っていれば動的口径サーベイ (x・y、δ = zrange、DAturns 周)。
 窓の外なら DA = 0 を記録 (チューンの補正はない)
   ▼
 書き出し: 全要素の COD・分散のずれ (ResultWrite)、補正磁石の K0 (WriteKick)、PM での統計 (RMSWrite)、DA
   ▼
 誤差と K0 を 0 に戻して次の種へ
```

誤差の想定 (DDBA の記録と一致): 据え付け 50 μm、強さ 0.05%、回転 0.1 mrad、±1σ カット、種 100 通り、on-momentum の DA が最悪 30σ・平均 40σ (β = 21 m、εx = 830 pm rad で 30σ = 4 mm)。2.5 GeV 版 (`_2`) は位置ずれを半分 (25 μm) にしてある。

### 4.2 何が「ずる」か (実機にない手順を、コードから特定したもの)

1. **誤差を段階的に入れる**: 実機の据え付け誤差は一度に全部入る。ここでは位置ずれだけを 1/5 から順に大きくし、前の段階の補正済みの状態から次に進む。強さの誤差・回転の誤差は初めから全部で、段階的にしない (台本のコメントは位置ずれの大きさ ae = 10・20・30・40・50 μm とだけ書く)。K64 の `cell calc` は、位置ずれの倍率を変えて呼び直したとき、COD が更新されないことがあった (同じ乱数の誤差を、倍率 1 → 0.5 → 0.2 → 2 の順に与えて `cell calc` を呼ぶ試験で、1・0.5・0.2 では COD が変わったが、0.2 の次の 2 では前の値のまま。pysad (k64) も同じ値)。段階的に上げる理由は、前の状態が COD の初期値になるため解が求まりやすいから、と考えられる (台本に理由の記載はなく、確かめていない)。
2. **補正の失敗の扱いが無い**: 台本は補正が収束したかを調べない。`Twiss` を読むだけで、COD が求まらなかった (`closed orbit not found`) ときも続行する (その場合、gs は Twiss が 0 を返し、pysad は前の値のまま残るので、表示の rms が 0 や前の値になる)。最後にチューンが窓の外の種を DA = 0 と記録するだけで、補正が効かなかった種かどうかは区別しない。
3. **応答行列は設計の解析式**: 実機のように補正磁石を振って測った行列ではない。誤差のない理想のラティスのツイス・位相進みから作る (誤差のあるラティスの応答との違いは、ゲイン 0.5 の反復で吸収される)。
4. **モニターは理想**: SAD の COD (`Twiss["DX","PM*.*"]`) をそのまま読む。モニターの位置ずれ・読み取りノイズ・ゲイン誤差がない (モニター PM* は位置ずれの対象 `{BQSHV}*` にも入っていない)。
5. **補正磁石は理想**: K0 を直接実数で設定する。電源の分解能・キャリブレーション誤差がない。補正磁石 (HD・VD) 自身の位置ずれは乱数に含まれるが、L = 0 なので効かない (この例では、K64 の問題を避けるため VD の位置ずれは 0 に戻した。下の 6 節)。
6. **反復の回数**: ゲイン 0.5 で 5 回 (最後の段階だけ 50 回)。実機の測定→補正の数回より多く、収束させている。補正は水平・垂直を独立に行う (結合は無視)。
7. **同じ乱数の実現を拡大**: 各段階は別の誤差の実現ではなく、同じ誤差の実現の大きさを変えたもの。
8. **チューン・分散・β の補正は無い**: 補正するのは COD だけで、チューンのずれ (誤差でどれだけずれたか) は結果として記録されるだけ。窓の外のチューンは DA = 0 にする。元のフォルダに `modules_correctoptics.n` (分散・COD・β の応答、固有値を選ぶ補正) があるが、v07_14 のどの台本からも読み込まれない。
9. **乱数の設計**: `SeedRandom[187]` から作った 1000 個の表の k 番目を種にする (種の値は `seeds[k]`)。同じ種は同じ誤差を作る (gs と pysad で同じ乱数列になることを確認した: 同じ種で、補正前の COD が 10 桁一致)。

### 4.3 例の設定の結果 (種 2 個、段階 5、補正 3+3+3+3+10 回、5 GeV)

## 6. 元のスクリプトの問題と直したもの

1. **元のスクリプトはラティスを読み込まない**: `gs ラティス スクリプト` と 2 つ並べて走らせる使い方で、スクリプト単体では動かない (前提が無い)。→ 例の台本は、ラティスを先頭に貼った自己完結のファイルにした。
2. **`matching_v07_13` のチューンの打ち間違い**: nx0 = 45.865、ny0 = 21.665 (v07_14 は 47.865・16.655)。→ `matching_v07_11` を使う。
3. **誤差の計算の補正が効かない (K0 が成分ごとに効かない)**: 補正磁石 HD・VD は、リングの中で同じ要素名の繰り返しなので、既定の (EXPAND の) `cell calc` は K0 を全部同じ値に揃える。`LINE["K0","HD.7"] = …` と書いても、HD.1 の値だけが全部に効き、ほかの成分への代入は読み戻すと 0 のまま (試験: HD.1 に 1e-4 を入れると COD が 2.7 mm、HD.2〜HD.12 に入れても COD は変わらない)。元の台本はこの状態のまま補正を繰り返すので、補正が効かず、`closed orbit not found` になる (元の台本を、種 2 個・補正を減らして走らせて確認: gs は補正のあとのチューンが 0 になり (closed orbit not found)、pysad は補正を繰り返しても rms が下がらない)。→ `USE RING NOEXPAND` と `cell calc noexpand` を使う (docs/29 A56)。
4. **垂直補正磁石 VD の位置ずれ**: `ROTATE = -90 度` の BEND (L = 0) VD は、位置ずれ (DX・DY) があって K0 が 0 でないと、`cell calc` が `closed orbit not found` になる (K64 の gs・pysad とも。試験: VD の位置ずれを 0 にすると K0 が効く。HD は位置ずれがあっても効く)。→ 補正磁石の位置ずれは L = 0 の要素に物理的に効かないので、VD の DX・DY を 0 に戻す (乱数の列は元のまま: `DELX` は VD にも与えてから 0 に戻す。補正の対象 `{BQSHV}*` を `{BQSH}*` にした)。
5. **DA を先に走らせると、書き出す値が補正後の状態でない**: `DynamicApertureSurvey` のあとは `cell calc` のチューンが変わる (47.865 → 47.98。原因は追っていない)。元の台本は DA のあとに COD・K0・統計を書き出していた。→ 書き出しを DA の前に移した。
6. **`RMSWrite` の「チューンのずれ」の列**: 旧い設計のチューン 48.6・12.7 を引いていた (v07_14 は 47.865・16.655)。→ 設計のチューンに直した。
7. **出力ファイル名**: `correct_cod_v07_14_grad_res` は `datas*_v07_16_1.txt` (v07_16 のコピーの名前) に書く。→ `V0714_correct_cod_5GeV_*.txt` に。
8. **`CalculateCODResponse` の無駄**: 補正磁石の数 (240) 回の `cell calc`。→ 除いた (結果は変わらない)。
9. **`calc_chromaticity.sad` の末尾**: 未定義の変数 (`nx0`・`ny0`・`emitring` など) を `Print` する。→ 除いた。
10. **K64 のバグ B18 の影響 (直していない)**: `PolynomialFit` を δ を ±対称に振ったデータに使うと、係数が壊れる (docs/29 C6、docs/30 B18)。元の `matching_v07_11`・`calc_chromaticity.sad` が出す「係数 [1,2]」は ξ ではない。例: 6 極 0 の RING で、係数 [1,2] は x が −21828、中心差分の ξ は −67.7 (DDBA の記録の自然クロマティシティ −67.7 と一致)。→ 元の出し方 (係数 [1,2]) を残し、**中心差分の ξ を足した**。
11. **使われないモジュール**: `modules_correctoptics.n` (分散・COD・β の応答行列、固有値を選ぶ補正) は v07_14 のどの台本からも読み込まれない。`modules_matching_noID.n` は `matching_v07_11` が Get するだけで使わない。→ 取り込まない。
12. **元の台本のコメントの数字**: `correct_cod_v07_14_grad_res_2` (2.5 GeV) の「ae 20um」などの表示は 5 GeV の値のまま (ae = 25 μm なので実際は半分)。→ 段階の表示を実際の ae から出すようにした。
13. **`FitValue` の定義の順序**: `matching_v07_11` は各 fit 条件の直後に `FitValue` を定義する。まとめて先に定義すると、TCELLA のマッチングが収束しなかった。→ 元の順序のまま。

## 7. 未確認・限界

- 元の台本の本来の環境 (台本が走っていた SAD のバージョン) は分からない。この環境の SAD K64 (gs) と pysad (k64) で、6 節の 3・4 の問題が出る。元のバージョンで動いていたか、動いていたとして結果がどう違うかは確かめていない。
- **DA の gs・pysad の食い違い (`ExpandElementValues->True` の既定)**: 上の 4.3 のとおり原因は確定していて、`ExpandElementValues->False` で一致する。pysad の DA は周回数 200 周・1〜2 種・δ 3 点だけなので 100 種の統計ではない。2.5 GeV の DA は `False` で、gs・pysad とも 2 種・x・y・on-momentum で 51σ (DAPWIDTH の上限) で一致 (`errors/V0714_correct_cod_2.5GeV.expandfalse.*.txt`)。
- gs と pysad の △ (3 節の注記): セルの6 極の色収差補正 (`DP = 0.01` の長直線部のセルの FIT) で gs と pysad の K2 が違う。ξ・6 極つきの値が 0.01〜0.1 違う。誤差の計算 (COD の補正) のあとのチューンは gs と pysad で 1e-4 程度、COD の rms は 3 桁目から違う。
- チューンサーベイは設計値から毎回再マッチングする。設計から遠い点の収束と、DA など非線形の量は確かめていない (サーベイは ADTS・ξ まで)。完全な設定の `*_full.sad` は走らせていない (見込み時間は外挿)。
- 6 極の最終設定 (20231205 の再調整版) は、このスクリプト群の出力ではなく、別のソフトで別の研究者が最適化した結果を入れたもの (冒頭の公開論文の注意を参照)。`V0714_match_tune`・`V0714_chrom_cell` の6 極の補正 (S3・S4 の色収差補正) は、その最終設定を再現するものではない (`chrom_v07_12rev` は S1・S2 を 0 にして S3・S4 だけで補正する旧い版の道具)。
- 2.5 GeV のラティスは、元の `v07_14_2.5GeV` (古い6 極の組) ではなく最終設定の6 極にしてある。元の `v07_14_2.5GeV` のままで走らせた結果との違いは確かめていない。
- 元の台本は、補正に失敗した種 (COD が求まらない) を検出しない。例の設定の種では失敗は出なかったが、100 種では出る可能性がある (確かめていない)。
- ラティスは設計値で、ID・ウィグラー・入射の要素は入っていない。RF 電圧は 5 GeV で 6.5 MV (`v07_14`)、2.5 GeV で 1.6 MV。
