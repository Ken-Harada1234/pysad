28. v2 (既定) と k64 (PYSAD_COMPAT=k64) の違い

この文書で分かること: pysad の計算結果が v2 (既定) と k64 でどこが違うか。K64 (SAD の公式配布版の実行系。gs はその実行ファイル) の誤りを v2 が直しているため、同じ入力でも値が変わる機能の一覧である。 前提: 数値を gs (K64) と比べたいとき、または K64 と同じ結果が欲しいときは PYSAD_COMPAT=k64 を付ける。それ以外は v2 のままでよい。 読む順: 互換モードの使い方 → 自分の機能の表 (§1 放射・光学、§2 スピン、§3 追跡・要素、§4 数学関数、§5 スクリプト) → §6 の確認状況。

pysad には互換モードが 2 つある。v2 (既定) は K64 のバグを直した動作、k64 は K64 (gs) と同じ結果を出す動作である。この文書は、モードで結果が変わる機能・動作の一覧である。K64 側の誤りの本体と B 番号は 30_sad_bug_report.md、未実装・未確認・限界は 31_unimplemented_and_unverified.md にある。

互換モードの使い方

項目 内容
モード v2 (既定): K64 のバグを直した動作。k64: K64 (gs) の動作
切り替え 環境変数 PYSAD_COMPAT=k64 (または v2)。Python からは from pysad import compat; compat.set_mode('k64') (None で環境変数に戻す)。compat.mode() が現在のモード、compat.v2()・compat.k64() が真偽
試験・回帰 gs との数値比較の試験と回帰 (pysad/tests/regression_tests/run_regression.py) は k64 で走る (pysad/tests/script_tests/conftest.py が PYSAD_COMPAT の既定を k64 にする)。v2 の動作の試験は test_v2_*.py で、フィクスチャ v2_mode で v2 を明示する
gs と比べるとき PYSAD_COMPAT=k64 を付ける。py -3.12 run_sad.py lattice.sad script.sad の既定は v2
内部の約束 追跡のカーネルが rs[1] (v2 の印) を読むので、rs は必ず track6n.make_rs() で作る
  • この表に入れないもの: モードによらず同じ動作の機能 (K64 にない新機能、K64 に無い機能・動かない機能のうち gs と同じ結果が出るもの、pysad 自身の不具合の修正、DAPWIDTH の既定 7 など両モードで同じ既定) は含めない。新機能の解説は各機能の文書 (docs/13〜22、24〜26) にある。
  • k64 モードも K64 と完全に同じではない点がある: gs に合わせて、(1) For の本体を実行しない (B71)、(2) 利用者のコードの BeginPackage・Begin が名前空間を作る。また、gs が真値を返すのに pysad の値が誤っていた点 (B183・B185〜B196・B199 の一部) は、k64 でも真値にしている (該当行に書いた)。
  • 表の「根拠」は、v2 の動作を確かめた基準 (解析式・独立な数値計算・厳密な幾何・gs など) と B 番号。数値の細部は 30_sad_bug_report.md と試験 (pysad/tests/script_tests/test_v2_*.py、test_v24_*.py、test_v241_*.py) にある。
  • 確認できなかった点は §6 にまとめた (「要確認」と書いた行)。
