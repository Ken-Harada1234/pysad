05. SADScript 言語と pysad のインタプリタ

最終更新: 2026-11-23 (現状のスナップショット)

この文書で分かること: SADScript (SAD に内蔵された式言語) の文法と評価の規則、pysad のインタプリタ (sadscript.py) がどこまで対応しているか、対応していない構文、SAD の Fork・文脈 (BeginPackage) などの特殊な機能の扱い。 前提: Mathematica 風の式言語を読める。FFS (SAD の対話コマンド部) の基本は 03_ffs_commands.md §1 を先に見ると、MAIN 部・FFS 部の区別が分かる。 読む順: §1 (全体と使い方) → §2・§3 (文法と意味) → §4 (入出力・書式) → §5 (SAD 独自の関数) → §6 (対応していないもの・特殊な機能)。特殊関数・Fit・SAD の Packages は 06_sadscript_library.md。

対象のコード: pysad/sadscript.py (字句解析・Pratt 構文解析・評価器、約 4800 行)、pysad/sadlist.py (リスト・文字列・行列の関数)、 pysad/sadelem.py (FFS 専用関数)、pysad/teigen.py (Eigensystem)、pysad/sadclass.py (Class)、pysad/pkgload.py (Packages/*.n の読み込み)、pysad/specfn.py・fitroot.py・miscfn.py・fileops.py (特殊関数・Fit・ファイル関数など)。SAD 側の根拠は src/tfetok.f (字句)、src/tfstk.f (演算子表 opcode/iprior)、src/autofg.f (数値書式)、 Packages/Fit.n (PolynomialFit)、src/tffsa.f (FFS コマンドの振り分け)、src/teigen.f、src/tmatch.f。

1. SADScript の概要と SAD 内での位置付け

SADScript は SAD に内蔵された Mathematica 風の式言語である。f[x, y] の関数呼び出し、{...} のリスト、 x_ のパターン、-> の規則、#& の純関数、/@ の Map など、表記はほぼ Mathematica と同じだが、 数値は倍精度実数のみ (整数型・有理数・任意精度はない) で、True/False も 1/0 の実数である。

SAD のスクリプトは MAIN 部 (ラティス定義) と FFS; 以降の FFS 部に分かれる。FFS 部では各文を tffsa.f が先頭の語で判定し、CALC, FIT, FREE, GO, USE, CELL, EMIT などの FFS コマンド (abbrev(word,'DELW_AVE ','_') のような省略形付きの比較) と照合する。SAD では先頭の tfprint (tffsa.f:245) が itfpeeko で先読みし、定義済みシンボルや name[, name= のように式に見える語はコマンド照合より先に SADScript として 評価する (03_ffs_commands.md §1)。pysad は判定の向きが逆で (コマンドでなければ式)、Interp.run(src, 'ffs') が文ごとに _is_ffs_command (先頭語が ffs_words に登録されたコマンドか、かつ続きが =, [, ( などで 始まらない) を見て、コマンドなら ffs_handler (ffscmd.py の FFS.execute) へ文字列のまま渡し、 それ以外は parse → eval する。

モジュールは Get["file"] で読み込む。SAD は起動時に Packages/init.n を読み、functions.n, MessageName.n を Get し、Fit.n (PolynomialFit, FindRoot) や Matrix.n, Optics.n などは AutoLoad[symbol, file] で最初に使われたときに読む。pysad では Get はファイルを読んで run(src, 'ffs') するだけ。Packages は、環境変数 PYSAD_SAD_PACKAGES のフォルダ (最優先)、無ければ pysad に同梱した SAD のコピー (pysad/sad_copy/Packages)、それも無ければ pysad の隣の SAD-master/Packages が見つかるとき pkgload.py が AutoLoad と同じく最初に使われたときに読む (CorrectOrbit・MakeBump・Monitor・Steer・OptimizeOptics・D・rational・tableform など。06_sadscript_library.md §5)。見つからなければ何も登録せず、必要な関数は Python 側の組み込みで動く (PolynomialFit は Fit.n の定義文字列 _PRELUDE を起動時に評価する。Python で持つ関数はパッケージの定義で上書きしない pkgload._protect_builtins)。Tkinter.n・KBFrame.n・ListPlot.n・Plots.n・Canvas.n も同じ方法で読む (20_tcltk_gui.md、04_ffs_small_commands.md)。

1.1 動かし方 (最小の例)

  1. 式だけ試す (FFS コマンドなしの 'script' モード):
import io
from pysad.sadscript import Interp
o = io.StringIO()
I = Interp(out=o)
I.run('f[x_,y_:2]:=x+y; a={1,2,3}; Print[f[1], " ", a[2], " ", 3<>4, " ", "a"//"b"]', 'script')
print(o.getvalue())      # → 3 2 1 ab
  1. ラティス付きのスクリプトは py -3.12 run_sad.py lattice.sad script.sad (SAD の gs に複数ファイルを連結して渡すのと同じ)。ffscmd.run_sad が MAIN 部を parser.py に、FFS 部を Interp.run(src, 'ffs') に渡す。Packages は同梱のコピーが使われる (環境変数は要らない。別の SAD の Packages を使うときだけ PYSAD_SAD_PACKAGES にそのフォルダを指定する)。

2.2 字句の規則 (tfetok.f)

  • 演算子は長いものから照合する (//., ^:=, ===, <=> → 2 文字 → 1 文字)。ただし =., /., //., ++, -- の直後が数字なら短い方に戻す (tfetok.f の case (mtfreplace, mtfunset, …))。 したがって x=.5 は x = 0.5、a/.5 は a / 0.5、i++1 は i + +1 である。pysad の tokenize も同じ分岐を持つ。
  • . の直後が数字なら数値 (eval2)。数値は 1.5, .5, 1e-3, 1d-3 (Fortran 形式の d も可)。
  • 暗黙の積: 2 Pi, a b, 2 (x+1), 2Pi は Times として解釈する (SAD と同じ)。改行をまたぐときは積にしない。
  • ! から行末までがコメント。(* ... *) もコメント。文字列は "..." (または '...') で、エスケープは tfetok.f の kxmakestring と同じ: \n \r \t \f \e (ESC)、\ + 8 進 1〜3 桁 ("\101" は A、256 で折り返す)、\x + 16 進 2 桁まで、\u + 16 進 4 桁まで、\ + 改行は行継続、それ以外は \ を落として次の文字 (\q は q)。 pysad は strip_comments で文字列の中を保護しつつ先に落とす。
  • \ + 改行は行継続 (tremovecont)。
  • シンボルは英字・$・` で始まり英数字・$・` が続く。x_, x__, x___, x_Real, _Real はパターン語として一語で読み、pysad では tokenize_full が Pattern[x, Blank[Real]] 等に分解する。

純関数 body& は Slot を引数に置換 (subst_slots、内側の Function には入らない)。Function[{x,y}, body] は名前束縛

反復 Do, Table, Sum, Product の反復子 {i, a, b, d} / {i, list} / {n}。Sum/Product は複数反復子可。Table/Do/Sum の {i,{a,b,c}} 形式は SAD でエラー。反復変数は Module の局所名より優先して束縛する
制御 If, Which, Switch, While, For, Return (例外 _Return)、Break/Continue、Catch/Throw、Check[e, fail]。Return は純関数・Do・Scan・Module・Block を抜けて、外側のユーザー定義関数 (:=) まで届く (SAD と同じ)。関数の外では General::unexpbreak でその文を打ち切る。Which/Switch は一致なしのとき式を返す (Which[1>2,"a"] は未評価のまま。Switch[a,1,2] は Switch[5,1,2]、引数がすべて定数なら SAD が読み込み時に畳むので Switch[9])。引数の個数の誤りは General::narg。For は 4 引数のときだけ評価し、3 引数は未評価で返す (k64 モード。本体 (4 番目) の扱いは v2 と k64 で異なる。§6 の For)
代入演算 ++, --, += 等は Set を経由するので a[[i]]++ も動く。AppendTo
改行と ; split_statements が括弧の外の ; と改行で文を切る。行末が演算子 (+ - * / ^ = , < > & \| : @ . ~) なら次行へ継続 (_incomplete)。ただし free Q* のように英数字直後の * で終わる行はワイルドカードなので継続しない。括弧の中では改行は空白
式 head f[a][b]、(f@g)[x]、Function[..][x] のように head が式でもよい
実行時エラー 最上位の文での Python 例外 (TypeError など) は SAD の ???General::wrongtype と同じく、その文を打ち切って続行 (PYSAD_TRACE=1 で traceback)

4. 入出力と書式

  • Print[a, b, …] は引数を文字列化して連結し、PageWidth (既定 131) で折り返して改行付きで出力。 Write[unit, …] は同じく改行付き、WriteString[unit, …] は改行なし。unit 6 は標準出力。
  • OpenWrite[path]/OpenAppend[path]/OpenRead[path] はユニット番号 (10 から) を返し、Close[unit] か Close[{u1,u2,…}]。$Output (= -1) への Write・WriteString は標準出力 (unit 6 と同じ)。Write[$Output] (引数 1 つ) は General::narg。 相対パスは Interp.cwd (run_sad では最後に渡したスクリプトのディレクトリ)。 OpenRead の失敗 (SAD と同じ): 開けなければメッセージを出して入力行を打ち切り、戻りの値に対する Read[h,…]・Close[h] は wrongtype になる (test_evalfixes.py。入力ファイルが無い場合がこれに当たる)。
  • Read[unit, item, opts] は SAD の tfreadstringf と同じ規則 (記録 = 1 行の中の位置を持つ)。Word は WordSeparators (既定は空白・,・タブ・改行) で区切り、語が記録の終わりなら次の記録へ (ReadNewRecord->False ならそのまま)、NullWords->True で隣り合う区切りの間に ""。Real は語を読んで評価、String と ReadString は記録の残り、Character は 1 文字、Expression は現在位置から 1 つの式 (隣り合う項 x+y 3*4 で切り、括弧が閉じなければ次の行も使う) を評価して返す。{item,…} はリスト、n*item は頭が Null のリスト (Print で連結される)。EOF は EndOfFile。ReadList・Get は上の §1 のとおり別。
  • DateString[t] は t (1900-01-01 0:0:0 からの秒、または {Y,m,d[,H[,M[,S]]]}) を mm/dd/yyyy HH:MM:SS にする (7 番目の offset は無視、未確認)。System[cmd] は、既定では実行しない (下の §6。EPICS の Ca* も動かさない)。ToString[x, form], StringJoin, StringForm あり。
  • リストの文字列化は {1,2,3} のように , だけで区切る (空白なし)。文字列はリストの中では "..." 付き。 PageWidth を超えると SAD と同じく , の後で折り返し、続きの行は 1 空白から始める (wrap)。 入れ子の長いリストの折り返しは SAD (要素の境界で改行、行の上限は pw-1) と pysad (区切りのカンマ、上限 pw) で異なる (PageWidth が十分大きければ一致)。
  • Print[Null] / ToString[Null] は Null (リストや関数の引数の中では空)。Expr の表示は f[a,b] (カンマ後に空白なし)。
  • 複素数の表示: I、(-I)、(re+I)、(re-I)、(re+im I)、虚部が負なら (re<虚部の書式> I)。

4.1 数値の書式: $FORM と fmt_real

$FORM (数の出力書式を決める SAD の変数) が "" または "S" のときは最短の往復可能表現 (_autos: 0.5, 5.07590922e-16)。 "15.10" のような 幅.小数桁 を指定すると autofg.f を直訳した fmt_real が使われる。 特徴は、整数部が 0 のとき 0. を書かず .0000000000 とすること、小数桁に収まらない小さな数は E 形式にすること、先頭に 1 文字の符号桁を取ること。S/M/C 前置 ("S15.10") は末尾の 0 と 空白を落とす。F/G/E 前置は Fortran の編集記述子そのまま。次の表は、同じ値を三つの $FORM で出したときの表示。

値 "15.10" "S15.10" ""
7.4210230634 7.4210230634 7.4210230634 7.4210230634
0 .0000000000 0 0
5.07590922e-16 5.07590922E-16 5.07590922E-16 5.07590922e-16
-0.0012345678901 -.0012345679 -.0012345679 -0.0012345678901

内部では _strfromd (18 桁の数字列と 10 の指数)、_roundnumstr (指定桁で四捨五入、桁上がりで 指数を 1 増やしてやり直し) を autofg.f と同じ手順で行う。FFS 側のマッチング表示 (tffsmatch の 1PG11.4) は fmt_g(x, 11, 4) で、0.1 ≤ |x| < 10^4 なら F 形式 + 4 空白、それ以外は 2.5977E-03 のような 1PE 形式になる。整数に近い値は 1080. (小数点付き)。

5. SAD 独自の関数

5.1 数値・行列・乱数

  • PolynomialFit[data, nord] (B18): Packages/Fit.n の定義を _PRELUDE としてそのまま評価する。v2 モードは x の平均が 0 のときの係数の誤りを直す (下の xl=1 の癖は k64 モードの動作)。例: {{-1,1},{0,0},{1,1},{2,4.1},{-2,4}} の 2 次で k64 は {1.0257, 2.0486, 1.0143}、v2 は {-.0085714, .02, 1.0142857} (numpy.polyfit と 1e-13 で一致。test_b18_polynomialfit_mean_zero_v2・_k64_and_nonzero_mean)。平均が 0 でないデータは両モードで同じ。v2 の判定は Compat$V2[] (互換モードが v2 なら 1) を prelude が使う。以下は k64 モードの説明。 データの x を平均 xa と scale=1/Max[Abs[x-xa]] で正規化し LinearSolve で最小二乗解を求めてから、 係数を元のスケールに戻す。ただし Abs[xa]*scale < 0.1 なら xa=0 とし、そのとき xl=If[xa, Table[…], 1] がスカラー 1 になる (リストでない) ので、cm = Table[...]/xl の除算も スカラー除算になる、という SAD の癖も含めて再現する。戻り値は {{c0, c1, …}, {Residual -> r}}。 numpy 版 PolynomialFit$numpy も残してあるが既定では使わない。
  • Spline[{{x,y},…}] は scipy の CubicSpline を包んだ純関数を返す (自然スプライン)。Spline[data,0,0] は SAD も pysad も未評価のまま。
  • 複素行列の演算: Dot・Inverse の結果は、SAD が要素ごとに虚部が 0 の複素数を実数に戻すので、pysad も要素ごとに戻す。DiagonalMatrix は複素数の列を受けて動く (LDSolve.n が動く)。Packages/Optics.n の TransferMatrix・BeamMatrix・NormalCoordinates・OrbitGeo も動く (SAD は 1e-16 の雑音の要素を出し、pysad は 0)。PeriodicR は PeriodicOptics を先に呼ぶ必要がある (06_sadscript_library.md §5)。
  • Eigensystem ({値, ベクトル}): 実行列は teigen.f の直訳 (pysad/teigen.py) で解く。固有ベクトルは単位ベクトルではなく SAD 固有の規格化、複素固有値の対は 行 k = 実部+i虚部 / 行 k+1 = 実部-i虚部。実行列の対称・縮退でも虚部の雑音が出ない。 ただし n>8 の実対称行列は np.linalg.eigh (SAD の teigen は縮退で丸め依存)。n<=8 や非対称は teigen の直訳。
  • LinearSolve (最小二乗 lstsq)、Inverse, Det, Dot, Transpose, DiagonalMatrix, IdentityMatrix, SingularValues。
  • Thread: リストのリストは転置、Rule のリストは要素ごとの規則、式は引数リストで分配。
  • Override[rules…]: 規則を平坦化し、同じ左辺は最初のものだけ残す (オプション処理用)。
  • Random/GaussRandom/SeedRandom: ffscmd.py が sadrandom.SadRandom (random_plugin_sad.c の LCG seed ← 48828125·seed mod 2^32、初期種 17、Box–Muller、GCUT 棄却) を割り当てるので、 追跡の FLUC と同じ乱数列を共有する。Random[n] は n 個のリスト (Random[0] は {}、リスト引数は wrongtype、負は wrongnum)、 Random[n,m,…] は n×m×… の配列 (行優先に順に引く。小数は切り捨て。GaussRandom・ParabolaRandom も同じ)。GaussRandom[] はスカラー。 SeedRandom[n] は種、SeedRandom[] は {"SAD", seed, filled, next の下位語, 上位語}。SeedRandom["SAD"] と、先頭が文字列のリストは乱数の種類の選択だけで 状態は変わらない (SeedRandom[状態] で状態は復元されない: SAD の tfRandom_.c はリストの数を読まない。数だけのリストは種 1 になる)。"SAD" 以外は System::error。
  • StringMatchQ: ワイルドカードは * (0 個以上)、% (1 文字)、{abc}・{^abc}、a|b (SADHelp の wildcards)。? は普通の文字、大文字小文字は区別、空文字列は何にも合わない。

6.2 文脈・For・FindRoot・MessageName・Parallelize・VISIT など (両モードの扱い)

文脈 (BeginPackage・Begin・End・EndPackage)

文脈 (名前空間) は、K64 (init.n の定義) の規則を写した。利用者のコードでは両モードで実装している。SAD 自身の Packages (.n) の読み込みは文脈を無視して大域で読む。名前は「現在の文脈 ($Context) → $ContextPath の順」に探し、無ければ現在の文脈に作る。BeginPackage[c1,c2,…] は $ContextPath を {c1,c2,…,System}にし、Begin[c]は$Contextを c にする。``x は大域の x。文脈の中の記号はStat名`` という名前になり、外からは ``Stat名` で呼ぶ。$Context・$ContextPath・Context[sym]` が読める。

  • 使い方: example/08_scripting/syntax_package_context.sad。大域に公開する関数は `Name[…] := … と定義する。大域の変数を使うときは `var と書くか、BeginPackage[My, ] のように $ContextPath に大域を入れる。組み込み関数・FFS の関数 (Twiss、LINE、FFS[…]、DP0 など) はそのまま使える。
  • k64 モードと v2 モードの違いは Names と、Begin に文脈を文字列で渡す形 (k64 は K64 と同じく拒否、v2 は受ける。Context["Ax"]の文字列も同じ) だけ: ``Names["Stat*"]は v2 がその文脈の記号の一覧、k64 が K64 と同じ{"Stat}。
  • K64 との意図的な差: (1) pysad の System` は組み込み関数 + pysad が記号として扱う名前 (AccuracyGoal・Plot などのオプション名を含む) で K64 より広い (K64 ではパッケージの中の AccuracyGoal は Stat`AccuracyGoal になり、`AccuracyGoal と書かないとオプションとして効かない。pysad はどちらでも効く)。(2) 表示: K64 は $ContextPath に無い文脈の記号に文脈名を付けて表示する (大域の記号が `sq になるなど)。pysad は文脈つきの名前だけ、$ContextPath にある文脈名を省く。(3) Symbol["Stat`x"] は K64 が値を返し、pysad は記号を返す。
  • $Context・$ContextPath への代入、WithContext、入れ子の文脈 (両モード): $Context への文脈の記号 (A の末尾にバッククォートを付けたもの) の代入と、文字列 ("AB" の形) の代入は init.n の $SetContext を呼び、読み取りの文脈が変わる (End の対象には積まない)。$ContextPath に文脈のリスト (A と System をバッククォートつきで並べたもの) を代入すると $SetContextPath。値が文脈でなければ ???General::wrongtype: Argument must be Context (Symbol ending ...) in $SetContext[…] (文脈はバッククォートで終わる記号) を出して元のまま。Begin は引数を $SetContext に渡すので、文字列で渡す Begin は拒否 (記号だけ。v2 は文字列も受ける)。WithContext[{c__},body] は BeginPackage[c]; Begin[First[c]]; body; End[]; EndPackage[] (body は文の読み取りの時点で名前が解決済み)。入れ子 A`B は一つの名前。Context[x] は文脈の記号を返し、文字列を渡す Context はエラー (k64)。文脈の記号は文脈が大域なので、大域が $ContextPath に無いとバッククォートつきの名前で表示する。K64 は x・l・a など init.n が大域に作った名前を、文脈の中で読んでも大域の記号に当たる (文脈 A の中で x=1 としたあとも Context[x] は大域): この 51 個の名前を pysad の大域の名前の初期値に入れた。使えない・未確認: 文脈つきの Names (K64 は状況で空のリストと文脈名のリストを返す。k64 は文脈名の一覧で規則が違う)、init.n が大域に作る名前の全部 (51 個しか調べていない)、System 文脈に入る名前 (pysad の System 文脈は K64 より広い)。文字列を ToExpression するときの文脈は「その時点の現在の文脈」。BeginPackage の戻り値 ({$ContextPath,""}) の K64 との一致は確かめていない (要確認)。SAD の Packages の読み込み (load_package、PackagesDirectoryの下のGet) は文脈を扱わず、PYSAD_SAD_PACKAGES` つきで GUI・描画・パッケージ系の試験が通る。

For、FindRoot の複素、MessageName の関数形

  • For[ini,cond,incr,body] (B71): K64 (gs) は 4 番目の引数 (本体) を実行せず、incr だけ繰り返す (3 引数は未評価)。Packages/functions.n の定義 For[`ini_,`cond_,`incr_,`body_]:=(ini;While[cond,body;incr];) どおりなら実行するはずで、同じ式を別名で定義すると K64 も実行する (原因は未特定の K64 の読み込み時の癖)。k64 モードは K64 と同じ (本体を実行しない。SAD の Packages は For を使っていない)。v2 モードは本体を実行する (Break・Continue も効く。3 引数は本体なしのループ。t = Σ i² = 30)。test_b71_for_body_v2・_k64。
  • 複素の初期値の FindRoot (B61): v2 モードは複素の Newton 法で解く (前進差分のヤコビアンと最小二乗の Newton 法、歩幅を半分にする減速つき)。FindRoot[z^2+1==0,{z,1.+1.*I}] → {z->(…+I),Residual->0}。連立も可 ({z*w==I,z+w==2})。MaxIterations・AccuracyGoal が効く。確かめた: z² = −1 → i、e^z = 2 → ln 2、z³ = 1、連立 zw = i・z + w = 2 (残差 1e-12 以下)。使えない: 変数の範囲 {var, ini, {min, max}} は複素では無視する、正則でない式 (Abs・Conjugate・Re・Im を含む) は収束を保証しない、実数の初期値で複素の値になる式は General::wrongval。k64 モードは TypeError。
  • MessageName[f,"usage"] (B70): K64 (gs) は関数形で f を無視して Undefined MessageName General::"usage" を返す。v2 モードは f の本文を返す (f::usage と同じ。無ければ General::tag の本文。General::mytag の継承は K64 の h::mytag と同じ)。k64 モードの pysad も f を見る (General::tag への継承だけ)。Message[f::usage] の表示は K64 が ???f::usage: 本文 を出す。pysad も出す (両モード): Message[f::tag, 値…] は ???f::tag: 本文 (本文の `1` を値で置換)、本文が無ければ General::tag、それも無ければ Undefined MessageName General::tag。Message[9, CA::open] の先頭の数は重大度。引数の評価で再帰するもの (Tkinter の未定義メソッド) では出さず、Tkinter::undef は出さない。Symbol["x"] は x の値 (未定義なら記号 x)。Off[f::tag] による抑止は未対応 (pysad の Off は何もしない)。例 example/08_scripting/syntax_symbol_message.sad。
  • Parallelize[f, n, lshare, npara] (両モード。pysad/fileops.py。Packages/shared.n の Fork・共有メモリ・Wait4 の動作に合わせた): POSIX (Linux・WSL・macOS) では npara > 1・n > 1 のとき os.fork で npara 個まで同時に f[k] を計算する (結果は子が一時ファイルに書き、親が回収)。結果の並びは SAD と同じ。子の代入は親に戻らない (親の変数は変わらない)。子の Print は出る (出力先が Python の StringIO のときは親に届かない: Fork と同じ)。lshare を超える結果は子が Shared::toolarge を出して $Failed (K64 は親が Timeout (2000 秒) まで待ち続ける)。Timeout 秒を超えた子は殺して $Failed。npara = 1・n = 1 は逐次。環境変数 PYSAD_PARALLELIZE=serial で逐次。Windows は逐次 (multiprocessing の spawn は Interp・FFS・ラティスを pickle できず、子の側で作り直す方式は f が参照する大域の状態を再現できないので実装していない)。WSL (Python 3.14) で、FODO の CALC を 8 通りの K1 で逐次と並列の結果がビット単位で同じ。4 つの Sleep[1] が 1.02 秒。条件: 親でカーネル (numba) を一度走らせてコンパイルとキャッシュを済ませてから呼ぶ。numba と fork の併用は実際には試せていない (WSL に numba が無く Windows に fork が無い。pysad のカーネルは parallel=True・prange・スレッドプールを使っていないので fork 後の子でそのまま動く見込みだが、(i) numba を parallel=True にする、(ii) 初回のコンパイルを子で行ってキャッシュ (__pycache__) を複数の子が同時に書く、(iii) OpenMP 版の BLAS を使う numpy、のどれかなら未確認)。例 example/09_io_system/fn_Parallelize.sad。試験 test_v2_B2_script.py。
  • VISIT・BYE・USE と ElementValues ほか (両モード): VISIT は FitFunction・FitValue・ElementValues・OpticsProlog・OpticsEpilog の 5 つの記号を隠し (訪問先では未定義)、BYE で戻る (入れ子も)、USE は 5 つとも消す (tffsa.f の tfblocksym・tfunblocksym)。BYE だけで VISIT が無いと ???-FFS-Error-BYE without VISIT.。BYE ALL は K64 が SIGSEGV で動かない (pysad は一番外側の値に戻す)。台本 FFS_VISIT_BYE.sad。
  • Ffs;・ffs use ring;: FFS と ffs だけが FFS の語で、Ffs;・FFs; は MAIN の構文エラー (SAD と同じ)。LINE 名は書かれたとおり (USE ring は ring が無いとエラー)。03_ffs_commands.md の FFS; の項。

6.3 Fork・Shared・Wait

  • 共有メモリ (両モード): s = OpenShared[n] (n バイト)、Shared[s] = 値、Shared[s]、Shared[s]++、Shared[s] += v、Close[s]。値は数・文字列・記号・リスト・式・規則 (無名の mmap に符号化して書く)。SharedSize[値] が n を超えると Shared::toolarge (K64 と同じ式: リストは (1 + 要素数) × 8 + 中身。SharedSize[{1,2,3}] = 32)。
  • Fork[]: Linux・WSL・macOS では os.fork で本当に分ける (親には子の pid、子には 0。子は Exit[] か最上位の文の終わりで os._exit)。Wait[] は {pid, status}、Wait4[pid, flags…] は {pid, 終了コード, Exited->…, …}、Kill[pid] はこの pysad が作った子だけ (安全のための制限)、Sleep[t] は本当に待って 1 を返す、Pause[t] は子がいる間だけ待つ。Windows には fork が無い: v2 は System::error: Fork[] is not available on this platform … を出して文を打ち切る (k64 モードは pid を返し子は作らない)。並列の計算は Parallelize[f, n, lshare, npara] (§6.2)。
  • 確かめた範囲: WSL (Ubuntu、Python 3.14、numba は代用の空モジュール) で例 (example/09_io_system/fn_SharedMemory_Parallelize_System_Fork.sad) と 3 個の子の試験。ラティスを使う重い計算を子で走らせる使い方 (numba のスレッドと fork の併用) は未確認。子の Print は親と同じ出力先に出る (出力先が Python の StringIO のときは親に届かない)。
