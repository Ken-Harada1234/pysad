pysad と SADHelp (1.4.4.2k64 Updated: 10/19/2026) の対応表 — SAD 側の定義場所つき

この文書で分かること: SADHelp の各項目 (FFS コマンド・関数・変数・要素) を、SAD 側のソースのどこで定義されているかと、pysad で実装済みか・未対応かの対応表。 前提: 項目の説明は docs/34_sad_help_index.md。表中の「実装」は名前が登録されているという意味で、挙動が K64 と一致するかは各要素の文書 (docs/13〜21 など) を見る。 読む順: まず §1 (FFS コマンド) と §2 (関数) で自分の使うものを引く。限界は §7。

最終更新: 2026-11-17 (現状のスナップショット。SADHelp は 1.4.4.2k64 Updated: 10/19/2026。pysad 側の列は 2026-11-16 の Interp.builtins と FFS の表から照合した)

機械照合 (perf_work/pysad_vs_sadhelp.py)。「SAD 側」は名前が登録・定義されているソース: Fortran (src/.f)、C (src/.c の REGn)、.n (Packages/*.n の定義)。? 付きは登録の形が見つからず文字列として出現するだけのもの。「pysad」は名前の登録の有無 (実装の深さは docs/03・04・12 を参照): コマンドは FFS._COMMANDS/_abbrev、関数は Interp.builtins、変数はソース中の参照、フラグは _FLAGS_DEFAULT/_SINO、要素は parser/sadkw。

読み方 (2026-11-16): 「実装」は名前の登録があるという意味で、gs (K64 の SAD) との一致の度合いは各要素の文書 (docs/13〜21) にある。 中身が簡単な代用にとどまるものは、行に「(限定: …)」と書いた。Packages/*.n の関数 (Plot・OptimizeOptics・CorrectOrbit など) は、組み込みの登録ではなく SAD 自身の .n を pysad のインタプリタで動かす (環境変数 PYSAD_SAD_PACKAGES が要る。docs/06)。機械照合が見るのは組み込みの登録名と FFS の表だけなので、 そうした行とユーザー定義フックの行は手で直してある。この表を perf_work/pysad_vs_sadhelp.py で作り直すと、手で直した行は消える。§6 を見て戻すこと。

7. 未確認・限界

  • 「実装」は名前が登録されているという意味で、挙動が K64 と一致するかは要素ごとの文書による。Interp.builtins の登録名は 2026-11-16 に実行時に集めた (462 個)。
  • 特別変数 (§3) は「ソース中に名前の文字列があるか」だけの照合。CASE・TITLE・Track$Excitation は参照が無く未対応。ElementValues は機械照合では参照なしに見えるが、Couple.n 経由で実装済み (§3 の行。VISIT/BYE の退避・復元は未対応)。
  • MessageName の関数形 MessageName[f, "usage"] は、v2 モードで f の本文を返す (gs は f を無視する: B70)。Skip は gs に合わせた。
  • Polarization (K64 が NaN: B55)、PHSROT (K64 で動作しない: B38) は v2 モードで実装している (k64 モードは NaN・NotImplementedError)。docs/16 (POL の v2 の動作の節)、docs/10 §9.7。
  • 要素のキーワード表 (§5) は 2026-11-16 の機械照合による。v2 のキーワード (UND の FBX・FBY、PHSROT の PX PY PZ・Dij・Bij、SOL の DZ・CHI1..3・AUTOPHI、CAVI・MULT の AUTOPHI、MARK の JDX JDPX JDY JDPY の読み方など) は反映していない (要確認)。
  • SADHelp は K64 版 Documents/SADHelp.html (1.4.4.2k64 Updated: 10/19/2026)。CERN の SADHelp は 1.4.0.0k64 2025-07-14 で同系統。KEK 公式の SAD ヘルプは別の SAD なので見ていない。
