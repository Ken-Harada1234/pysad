10. TrackParticles — 粒子追跡 (SAD の tturn 系と pysad の track6.py / track6n.py)

この文書で分かること: TrackParticles[] の引数と戻り値、1 周の追跡の中身 (要素ごとの写像、放射、乱数、損失判定)、pysad の 2 つの追跡器 (純 Python の track6.py と numba の track6n.py)、MAIN の TRACK、要素ごとの追跡の範囲、v2 (既定) と k64 (PYSAD_COMPAT=k64) の違い。 前提: SAD のラティスと FFS の基本 (docs/02・03)。光学計算 (docs/07)・エミッタンス (docs/09) が済んでいること。 読む順: 使うだけなら §1 と §9.1・9.7、ダイナミックアパーチャは docs/11、実装を追うなら §2〜§6。

用語: tturn = SAD の 1 周の追跡ルーチン。tapert = 損失 (絞り) の判定。TRPT = 輸送路モード (リングを周回せず 1 回通す)。LOSSAMPL = 損失の振幅の閾値。dv = 速度に関する補正量。k64 = SAD 本体 (K64) の動作の再現、v2 = K64 の誤りを直した pysad の既定の動作。

参照元: SAD ソース (<SAD>\src の tftrack.f, tturn.f, tapert.f, tdrift.f, tquad.f, tsolqu.f, tbend.f, tbendi.f, tcav.f, tmulti.f, tsol.f, photons.f, drndsr.f, random_plugin_sad.c, tgauss_.c, tfRandom_.c。行番号は 2026-10 時点) と pysad/track6.py, pysad/track6n.py, pysad/sadrandom.py。 追跡 (TrackParticles) は CALC/Emittance[] の経路 (tturne: tquade, tbende, tthine, tcave, tradke) とは別のルーチンを使う。pysad もそれに合わせ、光学計算 (lattice.py / emit6d.py) とは独立に track6.py を書いている。

1. TrackParticles[] の仕様 (tftrack.f)

TrackParticles[{loc, beam}, dest, nbegin, nend]
引数 内容 根拠
{loc, beam} loc は開始要素 (番号または名前)、beam は粒子リスト tftrack.f:74-86
dest 終了要素 (省略時 nlat = ラティス末尾) tftrack.f:64-73

1.1 周回ループ (tftrack.f:243-281)

  1. mt > 1 なら最初に tturn(npa, ls, nlat, …) (開始要素から 1 周の終わりまで)。
  2. 残り mt − 1 周は tturn(npa, 1, nlat, …)。npa ≤ 0 で打ち切り。
  3. 最後に tturn(npa, ls, ld, …) で終了位置まで。ld ≤ ls なら normal = .false. にして省略。

TrackParticles[{1, beam}, 1, 1, N] は N 周 (終点 = 始点なので最後の部分周回なし)。RFSW OFF のときは各周の終わりで z(1:np) = 0 (tturn.f:142-145)。

図の読み方: FODO リング (3 GeV、24 セル、6 極なし。NORFSW NORAD NOFLUC) の先頭 ORIGIN で、初期振幅 x0 = 1 mm の 1 粒子を 120 周追跡した結果。左は (x, px) 位相空間で、点が 1 つの楕円の上に並ぶ (実線は Twiss パラメータの不変量 γx² + 2αxx' + βx'² = 一定)。右は不変量の相対変化 J/J0 − 1 の周ごとの推移で、9e-4 以内に収まる (ほぼ保存する)。

図の読み方: 同じ FODO リング (RF 4 MV の版、追跡は NORAD NORFSW) の先頭で、水平振幅を変えて 200 周追跡した。横軸は振幅 [σx] (σx は EMIT の水平エミッタンス 1.7358e-7 m·rad と ORIGIN の βx から決め、1σ = 0.934 mm)。左は 1 周ごとの位相の進みから求めた νx の小数部 (青) で、橙の破線は線形のチューン (CALC の 0.6963)。1σ で 0.696366、10σ で 0.700032、20σ で 0.711219、30σ で 0.730067 と、振幅が大きいほどチューンが上がる (6 極がなくても、追跡が厳密なドリフトを使うため)。右は規格化座標の不変量 X² + P² の変動 (最大 − 最小)/平均 で、8.8e-4 (1σ) から 3.3e-2 (30σ) に増える。

1.2 NPARA > 1 での fork (tftrack.f:159-196)

NPARA (Packages/init.n の既定は 4) が 1 より大きいと tftrack は粒子を分割して itffork() で子プロセスに配る。

npara = min(NPARA, npz/npparamin + 1, ne*npz/npnlatmin + 1)     npparamin = 9, npnlatmin = 3000
  • 粒子が 9 個以上で分岐が起こる (8 個以下なら npz/9 + 1 = 1)。
  • 子プロセスごとに kseed = kseed + 2 として tfaddseed(kseed) を呼び、SeedRandom[現在の種 + kseed] で乱数の種をずらす (tftrack.f:629-)。したがって FLUC の乱数列を SAD と pysad で一致させるには NPARA = 1 をスクリプトに入れるか、NPARA=n; で同じ分け方を再現する (pysad の既定は NPARA=1)。子 k (k = 1, 2, …、条件 ipn + np1 < np かつ npr < npara) は乱数の種 = 親の種 + 2k で粒子 [ipn, ipn + np1) を追い、親は残りを元の種で追う (有効な並列数 = min(NPARA, np/9 + 1, ne·np/3000 + 1))。pysad の分け方は RAD + FLUC の追跡だけ (POL・RADLIGHT・PHOTONS・WAKE は分けない)。FODO リング (np = 200、1・10・100 周) の rms dp と最終の乱数の種が NPARA=1 と 4 の両方で gs と全桁一致、np = 16 (有効 npara = 2) の粒子ごとの dp も 12 桁一致、PF リング (760 要素、6 極つき、np = 40) も一致 (k64 モード。v2 は放射の式の修正で rms が 6e-6〜1e-3 違うが、乱数の引き方・最終の種は同じ。例 example/05_tracking/flag_FLUC_nparallel.sad)。
  • wake 有効時は並列化しない (tftrack.f:133)。wake は実装済み (13_wake.md)。

2. 内部座標と要素ループ (tturn.f)

2.1 tconvm — 入出力の変換 (tconvm.f)

向き 変換
入力 (idir < 0) px ← px/(1+δ), py ← py/(1+δ), dv = −δ(2+δ)/h1/(h1 + (1+δ)h0) + dvfs (h1 = √(1+p1²), p1 = p0(1+δ))
出力 (idir ≥ 0) px ← px(1+δ), py ← py(1+δ)

内部の運動量は px/p (全運動量で割った値) で、dv は粒子ごとの状態変数 (速度差 1 − v/v0 に相当)。dvfs は tsetdvfs (tturne.f:859) が merge(FSHIFT, 0, rfsw) で決める定数 (RFSW ON のときだけ FSHIFT)。放射でエネルギーが変わると dv も更新される (§4)。

dvfs が dv に足される場所 (追跡) (詳細は docs/history/work_small_items.md E): tconvm/tconv/tinip の入力変換、tradkn (photons.f) と trad/tsdrad/tserad/tqrad の放射後、tcav の h1 (p1r h0/(1−dv+dvfs)) と dv、tcavfrin、tmulti の空洞部。tcav の dvn (dzn) は含まない。pysad は _Phys.dvfs (track_particles(…, fshift=)、FFS の TrackParticles / DA / MAIN の TRACK は FSHIFT を渡す)。numba 版は状態 S を (n, 11) にして最後の列に dvfs を持つ。bench_level29e (NORAD/RAD/FLUC、FSHIFT=1e-6) が座標 ≤1.9e-11。

2.2 tturn / tturn1 — 要素外側・粒子内側

tturn(np, lb, le, x, px, y, py, z, g, dv, sx, sy, sz, kptbl, n, normal) → tturn1 が do l = lbegin, lend で要素を外側に回し、各要素ルーチンが粒子配列 x(np)… をまとめて処理する。pysad の _tturn1(parts, …) も同じ構造 (粒子ごとに要素を回すのではない)。これが乱数の消費順 (§4) とソレノイド内四極の癖 (§3.7) に効く。

2.3 tapert — 15 要素ごとの損失判定

  • tturn で la = 0 にして始めるので最初の要素の前に必ず tapert。以後、select を抜けた要素ごとに la = la − 1 し、la ≤ 0 で tapert を呼んで la = 15 に戻す (tturn.f:231-240, 553)。要素ループの後にも 1 回 (tturn.f:576)。exit で抜ける MARK 等では減らない (tsol 内のループは毎要素減る)。pysad は Prog.la_count で同じ数え方 (DRIFT/MARK/MONI は la を減らさない) をする。
  • tapert はまず limittrack (tturn.f:7-18): limitnan(a, x) = merge(x, merge(a, sign(x,a), |a| ≤ x), isnan(a)) — NaN は +x に、|a| > x は ±x に丸める。x, y は xlimit = 3·LOSSAMPL、px, py は 0.9999、z は 1e10。
  • 判定 (ax = ay = 0 の場合): −alost < x < alost かつ −alost < y < alost かつ |z| ≤ zlost を満たさない粒子を落とす。alost = LOSSAMPL (既定 1 m)、zlost = LOSSDZ (既定 100 m)。コメントにあるとおり NaN を落とすために「条件を否定した」形で書かれている。
  • 落ちた粒子は kptbl(i,4) = l_track, kptbl(i,5) = kturn を記録し、末尾の生きている粒子と入れ替えて np を減らす (tapert.f: Sweaping)。粒子の並びが変わるので、以後の乱数の消費順や §3.7 の癖に影響する。l_track はセッション最初の TrackParticles では 0 なので、その最初の tapert では最初から LOSSAMPL の外にいる粒子の印が 0 (生きている) になり落ちない (詳細は §9.5)。

2.4 APERT 要素 (tapert1)

  • キーワードの既定は全部 0: DX1 DX2 DY1 DY2 (矩形)、AX AY (楕円)、DX DY (中心のずれ)、ROTATE (回転)、JDPX JDPY DP、COUPLE (tapert は使わない)。光学では L=0 のドリフト、追跡だけで効く (SADHelp の APERT)。
  • tapert1 (tapert.f) は xl=min(DX1,DX2), xh=max(DX1,DX2), yl, yh も同様にして tapert を呼び、tturn の icAPRT の case は呼んだあと la = 15 に戻して exit (la は減らさない。tturn.f:417-423)。
  • 判定 (落ちない条件、tapert.f:78-174): eli = AX≠0 かつ AY≠0。eli で xh==xl または yh==yl なら矩形は ±1e100 (楕円だけ)。ROTATE≠0 なら xa = cosθ(x−DX) − sinθ(y−DY), ya = sinθ(x−DX) + cosθ(y−DY)、0 なら xa=x−DX, ya=y−DY。落ちない条件は (xa/AX)²+(ya/AY)² ≤ 1 (eli のとき) かつ xl < xa < xh かつ yl < ya < yh かつ |z| ≤ LOSSDZ。全キーワード 0 の APERT は矩形が空なので全粒子が落ちる。LOSSAMPL の判定は同じ式で ±LOSSAMPL の矩形・楕円なし・ずれなし。
  • JDPX か JDPY が 0 でないとき (tapert.f:32-60) は落とさず、(x/xa)²+(y/ya)² > 1 (xa=min(|xh|,|xl|)、ya も同様。0 なら制約なし) の粒子を tran_array の 2 個の乱数で境界へ入れ直す: x = xa cos φ1, y = ya sin φ1, px = JDPX cos φ2, py = JDPY sin φ2 (φ = 2π·乱数)、g += DP。DP はこの再入射のときだけ効く。dv は更新しない。
  • 落ちた粒子: kptbl(i,4)=l_track (= APERT 自身の要素番号)、kptbl(i,5)=kturn を記録して §2.3 と同じ入れ替え。TrackParticles の戻りの flag は 0、座標は落ちた時点の値 (limittrack の頭打ちを含む)。MAIN の TRACK の報告 P. id lost in n-th turn at l(APERT名), amplitudes: x y z は、TRPT でなければ出し、TRPT のときは l_track が APERT のときだけ出す (tapert.f:182-187)。
  • pysad: parser が APERT を Drift(L=0) に _apert=True と各キーワードの属性を付けて作る。track6n.k_apert_gen (numba、tapert.f 全体の直訳。LOSSAMPL の判定 k_apert も同じ関数)、k_apert_el (APERT 要素)、Prog._compile の K_APERT、turn。Python の追跡 (track6) は _apert_pass で同じ判定をし、落ちた粒子を末尾へ寄せる (track_particles(alive=…, zlost=…))。track6 には LOSSAMPL の判定 (最初の要素・15 要素ごと) はない。
  • gs との一致: 楕円・矩形・楕円+矩形・DX DY・ROTATE・全部 0・APERT 2 個・3 周・JDPX JDPY DP の flag と落ちた時点の座標 (tests/test_apert.py、3 GeV の FODO リング、RFSW/RAD なし、粒子 16 個)。
  • 未確認・限界: ソレノイド領域内の APERT (tsol.f:789 は tapert1 を呼ぶ) は、k64 モードでは未対応で NotImplementedError、v2 モードでは領域内の APERT で粒子が落ちる (9.7。スピン追跡の経路だけは未対応)。RAD・FLUC つき、TRPT、MAIN の TRACK の報告は gs と比べていない。JDPX/JDPY の乱数は粒子が 11 個以下なら gs と一致、12 個以上では gs が別の乱数列を使うように見え一致しない (原因は未調査)。DAPERT (動的口径) の追跡は APERT 要素を通すが、gs と比べていない。

3. 要素ごとのルーチンと式の要点

3.1 ドリフト tdrift_free (tdrift.f:10-32)

dpz = pxy2dpz(px,py) = √(1−px²−py²) − 1, al1 = L/(1+dpz): x += px·al1, y += py·al1, z += dpz·al1 − dv·L。近軸近似なしの厳密ドリフト。

3.2 四極 tquad (tquad.f:1-116)

L = 0 → tthin(nord=4)、K1 = 0 → ドリフト (bz≠0 なら tdrift_solenoid)。それ以外:

  1. tsolrot (DX, DY のずらし → 回転 theta2)。theta2 = ROT + akang で K1 < 0 なら π/2 を足す (焦点面の入れ替え)、ak = sign(K1L, L)。回転は chi3≠0 のときだけ行う (pysad の rot1 も th2=0 のときは回さない。x=inf, y=inf のとき 0·inf=NaN になるのを避けるためで、落ちる粒子の乱数消費 (§7) に効く)。
  2. 入口ハードエッジフリンジ ttfrin(nord=4, +ak) (DISFRIN=0 かつ mfring ≠ 2)。akk = ak/L/4 の x³, y³ 次の写像 (tquad.f:325-)。
  3. 線形フリンジ (FRINGE=1 or 3): a = f1in/p, ea = e^a, b = f2in/p で x ← ea·x + b·px, y ← y/ea − b·py, px ← px/ea, py ← py·ea, z も補正。f1 = −|akk·F1²|/24, f2 = |akk|·F2 (tsetfringep, tffs.f:952)。
  4. 本体: 放射なし tsolqu、放射あり tsolqur (入口で f1in ≠ 0 なら tradk(f1in))。
  5. 出口の線形フリンジ (FRINGE=2 or 3)、ttfrin(−ak) (mfring ≠ 1)、放射ありで f1out ≠ 0 なら tradk(f1out)、tsolrot の戻し。

tsolqu (tsolqu.f): eps = 0.2·EPS (EPS=0 なら 0.2)、ndiv = 1 + int(|L·hypot(ak, bz)|/eps)、各スライスは「半ドリフト → 厚い四極の閉じた式 (c1, s1, ch2, sh2) → 半ドリフト」。 tsolqur (放射あり): ndiv = max(ndiv, ndivrad(…))、スライスを外側、粒子を内側に回し、各スライスの後に全粒子まとめて tradk(np, …, aln, 0)。

3.3 薄い／厚い多極 tthin (tquad.f:118-322)

TENT (DX/DY/ROT の入口変換) → ttfrin(nord) (DISFRIN=0; 6 極 nord=6 は専用式、それ以外は一般次数) → 本体 → ttfrin(−ak) → 放射ありなら tradk(L) 1 回 → TEXIT。 本体 (L ≠ 0): drift(α₁L) → ½キック → drift(αL) → 補正キック (β, γ 係数) → drift(αL) → ½キック → drift(α₁L)、α = 1/√12, β = 1/6 − α/2, γ = 1/40 − 1/(24√3), α₁ = 1/2 − α の 4 次積分。キックは kord = nord/2 − 1, aki = K/kord!/(1+δ), cx = (x − iy)^kord, px −= aki·Re cx, py −= aki·Im cx。K は積分値 (pysad の Sextupole.K2 は長さあたりなので K2·L を渡す)。

3.4 偏向 tbend (tbend.f:531-673) と tbendi

  • ANGLE = 0: K1 = 0 → tsteer、phib = ANGLE + K0 = 0 → tquad、それ以外 → tmulti。
    • ROT の渡し方 (tbend.f:565-): tsteer / tquad / tmulti には theta+dtheta (ROT + DROT) を渡す (CALC の tsteee は theta だけ)。tsteer は L=0 → tthin(nord=2, ak=K0): px −= K0/(1+δ) (TENT/TEXIT)、K0=0 → ドリフト、L>0 → 入口エッジ tan(AE1) + 本体 (ndiv 分割、放射は各スライスの後に全粒子 tradk)。 垂直ステアリング (ROTATE=-90 DEG) は TENT で 90° 回した座標系で水平キックになる。BEND の ROT は Bend.ROTATE (+ROTATION) で、track6 _tsteer_ens/_tbend_ens、track6n の K_STEER/K_STEER0/K_BEND が読む。
    • ANGLE=0, K1≠0 の追跡 (tbend.f:566-590): K0=0 → tquad (theta+dtheta)、K0≠0 → tmulti。pysad は track6._bend_k1_proxy が QUAD/MULT の代理を作る (track6n は K0=0 を K_QUAD)。SAD の tquad 呼び出しは theta2 に akang を含めないので K1<0 の BEND は |K1| の集束四極として追跡される (29_sad_quirks A38、pysad も再現)。K1≠0 かつ K0≠0 は SAD が CALC で落ちるので追跡の照合はない。
  • K1 ≠ 0 → tbendi (tbendi.f): tbshift/tbrot → ttfrin(4) → FB1 のフリンジ → 粒子外側で ndiv = 1 + int(|ANGLE|/1e-3) (放射ありは ndivrad と max) のスライスを tbendiinit/tbendicorr/tbendibody で回す。rhoe = rhob·(1+δ) は入口で 1 回だけ決め、放射で δ が変わっても更新しない (k64 モード。v2 モードはスライスごとの放射のあとに更新する: 9.7)。放射は分割ごとに tradk1、最後に全粒子 tradk。
  • 純粋な偏向: tbshift(DX, DY, 回転) → DROT/CHI2 があれば tbrot(alg = L/2, phig = ANGLE/2) → tbendcore (入口エッジ psi1 → 扇形 → 出口エッジ psi2 を 1 ステップで写す閉じた式。フリンジ dxfr = fb²/ρ/24, dyfr = fb/ρ²/6) → 戻し。
  • 放射あり tbendr: ndiv = min(1024, ndivrad(phir, 0, 0, EPS))、入口・出口のフリンジ領域 fb/2 は iprev/inext = 0 のときだけ別スライス (n1 = −1, n2 = ndiv + 2)。各スライスで tbendcore → 全粒子 tradk。

3.5 空洞 tcav (tcav.f)

  • phis = 0 (TRPT) / phic (APHI≠0) / w·trf0。trf0 は Emittance[]/CALC が決める同期位相 (pysad は track_particles(trf0=…) で与える)。
  • offset の切り替え: rad .or. trpt .or. autophi なら offset = sin(dphis), offset1 = 0、それ以外は offset = sin(dphis) − sin(phis), offset1 = sin(phis)。RAD OFF では平均のエネルギー損失ぶんのキックを消す (放射損失がないので同期位相のぶんだけ打ち消す)。
  • tlim = 1e4 (RFSW) / 0 (NORFSW)。t = clamp(−z·h1/p1, ±tlim)、dh = max(oneev − h1, V·(−2 sin(ph) cos(ph − dphis) + offset)·wsn)、z = −t·p2r·p0/h2 − dzn。h1 は dv ≤ 0.1 のとき p1r·h0/(1 − dv + dvfs) から取る。
  • TRPT で VOLT≠0 の空洞は vnominal ≠ 0 で基準運動量が上がる。track6n.cav_full が tcav.f の ndiv 分割と p0、h0 の更新を写している (13_wake.md §3.2)。
  • 長さのある空洞: vnominal = 0 (リング) なら ndiv = 1 + int(min(|w·L|, …))、tcavfrin (DISFRIN=0, mfring ≥ 0) が入口・出口で x, y に比例した横キックとエネルギー変化。

3.6 多極 tmulti (tmulti.f:37-)

ANGLE ≠ 0 → tmulta (pysad 未対応)。それ以外: tsolrot → ttfrins(2n+2, akr[n]) (dofr(n): n ≤ 2 は非零で常に真) → [tsolqu / tsolqum (放射なし) / tsolqur (放射あり) の半幅 → n ≥ 2 のキック]×ndiv → 半幅 → ttfrins(−) → tradk → 戻し。akr[n] = K_n·cr1^(n+1) (cr1 は theta2 の回転)。ndiv0 は tpara が ampmaxm = 0.05 から決める。tsolqum の z の dv 項は −0.25(ap − dv)·aln0 で tsolqu の −dv·aln0 と違う (SAD の不整合、pysad は _tsolqu(qum=True) で再現)。

3.7 ソレノイド領域 tsol (tsol.f:510-)

tsol は BOUND ≠ 0 の SOL から次の BOUND ≠ 0 の SOL までを内部ループで追跡する。bzs = tfbzs(k) = charge·(BZ+DBZ)/(p0/c)。 入口: trots (CHI/DX/DY/DZ の座標変換) → F1 ≠ 0 なら tradks → DISFRIN=0 なら tsfrin(bzs)。出口: tsfrin(−bzs) → trots。 領域内: DRIFT は tdrift_solenoid (px += bzp·y/2 で回転してから戻す; 放射は粒子外側の tradkf1/tradk1)、BEND は双極キック付き tdrift、QUAD は tquad(bz = bzs) → ttfrin の bz 分岐と tsolqu/tsolqur の bz ≠ 0 分岐 (tzsetparams)、CAVI は tmultiacc。

癖 (tsolqu.f:465, 519-531): tsolqur の bz ≠ 0 分岐では bzp = bz/(1+δ_i) が各スライスの粒子ループ内で粒子ごとに設定されるが、スライス後の最後の半ステップ (do i = 1, np で xsincos(r·bzp)) は bzp を計算し直さないので、最後のスライスの最後の粒子の bzp が全粒子に使われる。RAD ON のソレノイド内四極の結果は粒子の並びに依存する (差は δ_i − δ_last に比例)。pysad は要素外側・粒子内側の構造 (_tsolqu_bz_ens → _tsolqu_bz_final(p, aln0, bzp_last)) でこれを再現している (Level 9 で確認)。

7. 検証と限界

検証: gs (K64) との比較は、小リング・実ラティスの 5〜500 粒子の 1〜100 周 (NORAD・RAD・RAD+FLUC、SeedRandom 付き) で座標が相対 5e-11 程度以内 (ベンチ Level 6〜12、16、25、29e)、RAD+FLUC は追跡後の乱数の状態まで一致する。ソレノイド領域 (Level 9) の RAD の行は保存済みの参照との比較で、現在の gs とは食い違う (SOL 領域内の四極 + RAD は gs 側の誤りの疑いが強く、原因は未特定: 9.8)。DynamicApertureSurvey の地図は 153 文字が一致 (docs/11)。ベンチごとの比較表は history/10_tracking_validation.md。 PYSAD_COMPAT=k64 で K64 と同じ結果が出る (v2 の既定は K64 のバグを直した結果。9.7)。

落ちる粒子の乱数消費: 粒子が落ちる周は、発散した粒子が tapert で除かれるまで光子の乱数を引き続ける (θ=π/2, anp≈94 なら約 100 個、NaN なら 1 個; §4) ので、その間の消費数を SAD と揃える必要がある。pysad は、sqrt1/pxy2dpz/asinz/norm2/xsincos の inf/NaN の出方 (§6.2)、tapert の la の数え方 (§2.3)、rot1 が th2=0 のとき回さないこと (§3.2)、tradkfn の max(gmin, g+dg) が NaN で gmin を返すこと (gfloor, §4) を合わせている。判定は SAD のデバッグ版との再同期テスト (各要素の全粒子の状態と seed を比べる。30 周・93 030 記録で seed 全一致) で行う。自由に走らせた最終 seed は、丸め誤差 (1e-11) の増幅で落ちる粒子の分かれ目が逆になるため一致しない (SAD 自身も初期座標の相対 1e-16 の摂動で変わる。詳細は上の検証ファイルと docs/history/work_loss_rng.md、work_loss_rng2.md)。

未対応 (両モード): SOL 領域内・COORD・TCAVI・MAP のあるラティスの光子 (PHOTONS の PhotonList は BEND・QUAD・MULT・SEXT・OCT・磁場つきドリフト・BEAMBEAM + BEND で対応: 9.7 (b))、BOUND=0 の SOL、wake のうち MULT の F1・FRINGE (docs/13)、BEAM/WIG 要素。k64 モードではさらに、SOL の DX/DY/DZ/CHI と F1、SOL 領域内の BEND・MULT・CAVI (§9)、空間電荷 (v2 モードは SPAC・PSPAC・WSPAC を入れる。9.7)。 (POL のスピン追跡、tmulta、COORD・TCAVI・UND・MAP、WAKE、BEAMBEAM は §9 で対応している。LOSSMAP は両モードで対応。)

9.2 POL のスピン追跡 (track6.py、docs/16)

POL かつ RAD が ON のときだけ、TrackParticles が粒子ごとのスピン (_Particle.s、bsi) を photons.f の sprot (tradk の中) の直訳で追う。RAD OFF ではスピンは変わらない (K64 も同じ)。 POL ON・RAD ON の fn_track は高速追跡 (TrackRun) を使わず Python の追跡 (track6) に切り替える。k64 モードでは LOSSAMPL の損失の処理 (§2.3 の tapert・flag) がなく粒子は落ちない (APERT 要素では落ちる。§2.4)。v2 モードでは track6 の経路でも落とす (9.7)。 入力は 9〜11 列 {x,px,y,py,z,dp, 角度, sy/|s|, flag}、戻りの 7・8 列は atan(sz, sx) と sy/|s| (スピン = (st·cos 角度, sy, st·sin 角度)、st=√(1−sy²))。 bsi (磁場の縦成分の積分) は四極 (tsolqur の各スライスの両端)、BEND (tbendcore の入口・出口、K1 のある BEND は tbendi の各スライス)、MULT (tmulti)、tdrift の ak0 付き、SOL 内のドリフトと四極 (bz·al) に入る。四極の ROTATE は tsolrot の chi3 のスピン回転。 gs と 4e-12 以下 (NOFLUC・FLUC): 平面リング、ずれ・回転のあるリング、MULT (K1 K2 K3)、K1 の BEND、SEXT、薄い MULT、SOL 領域内のドリフト (test_spin_track.py)。 未確認: SOL (bz≠0) 内の四極のスピン (下の差 ③ のため)、空洞・MAP のスピン。v2 モードでは SOL 領域内 (BEND・MULT・CAVI・ずれ・F1)、UND、PHSROT のスピン追跡が通る (9.7)。

9.3 RADLIGHT の軌道 (ffscmd._RadLight、docs/18)

TrackParticles は RADLIGHT のとき RAD と TRPT を ON にし、{{ls または ld, 座標}, 軌道} を返す。軌道は粒子ごとの {t, x, y, z} の 4 本の表で、RadiationField の入力になる。 K64 の tlinit・tlstore・tlresult の直訳で、gs と差 0 (2 粒子・複数周・始点 ls≠1、test_radlight.py)。K64 の癖: 記録するのは各区間 (tturn) の始めと、L≠0 の BEND 以外 (型 < CAVI) の要素の後だけで、BEND と曲げのある MULT の中は記録しない。 (k64 モード) tlinit が geo0 の軸 1・2 を設定しないので横方向の座標は軌道に入らない (進行方向に沿った点だけが並ぶ)。位置は straight (dphi=0) の積み上げで、BEND で向きが変わらない。 そのため、B を ANGLE=0 の STEER にする流れでないと、意味のある場にならない。v2 モードは軌道が実際の 3 次元の軌道になり、BEND の中も記録する (9.7、docs/18)。

9.4 SOL 領域の追跡の限界

k64 モード: 領域内に置ける要素は DRIFT、QUAD (K1≠0)、L=0 の要素、SOL。BEND・MULT・CAVI は未対応 (NotImplementedError)。領域内の直線 BEND は K64 の tsol.f どおりに tdrift(al, bzs, phiy, phix, …) を呼ぶ直訳を試したが、 gs は偏向をほぼ無視し (BZ=0.5 T で ANGLE=0.1 でも位置・角度の変化が 1e-5)、pysad の直訳 (ANGLE·距離だけ曲がる) と合わないので取り下げた。原因は未確認 (K64 側の癖かもしれない)。 v2 モード: 領域内の BEND・MULT・CAVI・APERT と、ずれて傾いたソレノイド (DX DY DZ CHI1..3・F1) に対応した。解析式 (ローレンツ力の数値積分) で確かめたもので、gs との比較ではない (9.7、docs/17)。

9.5 損失の処理

  • 損失の判定・入れ替えは tapert (§2.3) のとおり。高速追跡 (track6n.turn の apert) と MAIN の TRACK (§8) にある。track6 (Python) 側は APERT 要素の損失だけ扱う (§2.4。LOSSAMPL の判定はなく、POL のスピン追跡でも LOSSAMPL では落ちない)。
  • POL のスピン追跡の損失: k64 モードは処理なし (9.2)。v2 モードは track6 の経路でも落とす (9.7)。TRPT で最初から LOSSAMPL の外の粒子の扱いは次項。
  • セッション最初の TrackParticles の l_track=0 (gs と照合済み。k64 モードの動作。v2 モードは最初の tapert で落とす (B33)、9.7): K64 の tapert は落とす印に kptbl(i,4)=l_track を書く。l_track は tmacro のセッション変数で、セッション最初の TrackParticles では 0 (CALC をしても変わらない)。このため最初の tapert (tturn の最初の要素) では印が 0 = 「生きている」になり、最初から LOSSAMPL の外にいる粒子は落ちず、座標は 3·LOSSAMPL に頭打ちされて追跡を続け、後の tapert で落ちる。2 回目の TrackParticles からは l_track≠0 で最初の要素で落ちる。TrackRun.l_track0 と k_apert の lcur==0 で再現し、gs (1 回目・2 回目) と、元の K64 (B33 で SIGSEGV) を直した SAD (LOSSAMPL=1e-4、3 粒子 x0={1e-3,1e-6,2e-3}、NORAD、TRPT、2 周、15 値) と全桁一致 (test_small_items.py)。元の K64 は落ちるので「正しい基準」は直した版。B29: QUAD に RAD=1 を書くと COD・エミッタンスが 0 になるのはバグではなく仕様 (K64 は krad = (RAD_QUAD == 0) .and. al /= 0: tturn.f:360、tsol.f:677、tturne.f:572。要素の RAD が 0 以外ならその要素の放射を止める)。
  • COORD は tturn の exit なので la を減らさない (9.1)。MAP は落とす粒子をフラグ 0 で返せ、フラグ≠0 なら復活する。
