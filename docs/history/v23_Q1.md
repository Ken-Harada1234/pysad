## 2. 項目ごとの記録

### 2.1 設計の判断

| 欄 | 内容 |
|---|---|
| 追跡 | `track6n.TrackRun` を使う (numba)。SAD の TrackParticles と同じ tapert (最初の要素・15 要素ごと・区間の終わり、LOSSAMPL・LOSSDZ・APERT 要素)。新しい追跡のカーネルは書いていない。1 粒子あたり 0.25〜0.6 ms / 周 (ASTRID2 200 要素 〜 大きなリング A 3563 要素)、粒子数にほぼ比例するので、LMA の時間は (位置の数) × (1 位置あたりの追跡粒子数 ≈ 35〜45) × 周回数で決まる |
| 位置と区間の分け方 | 位置 loc から始めるのは `TrackParticles[{loc, beam}, loc, ...]` と同じ。**1 回の呼び出しで n 周と、1 周ずつ n 回呼ぶのとで、tapert の判定の位置が違う** (1 回の呼び出しは、最初の loc→nlat のあと 1→nlat の区間を (n−1) 回回す)。LMA (`track`、既定) は 1 回の呼び出しと同じ (gs の `TrackParticles[{loc, beam}, loc, 1, n]` と一致)、周波数マップ (周ごとの座標の記録) は 1 周ずつ (1 周ずつ呼ぶのと同じ) |
| 閉軌道 | 位置 1 の閉軌道を `Emittance[]` (RADCOD) から Newton 法 (有限差分のヤコビアン) で求め直す (残差 2e-18・4e-16)。ほかの位置へは 1 粒子の追跡 (FLUC なし) で運ぶ。RFSW OFF の δ ≠ 0 は 4 次元の Newton 法 (`closed_orbit_dp`) |
| RF バケット | `bucket_zlimit` = (π + 2|φs|)/k_rf (安定固定点の周りのバケットの端の位相 ψ = −π−2φs … π−2φs の広い側。φs = trf0·k_rf、k_rf = `wrfeff`)。この |z| の外へ出た粒子を落とす (LOSSDZ をこの値にする)。バケット判定を内部の追跡に入れず tapert の LOSSDZ に任せたので、gs と判定の機構が同じ |
| 周回数 | `ceil(nsynch/|νs|)`、nsynch の既定 2 (1 周期以上)。ASTRID2: 1312、大きなリング A: 491。直接指定が 1 周期未満なら警告 |
| 周波数マップの規格化 | 最初は位置 loc の Twiss (δ = 0) の α・β で x̂ − i p̂ を作ったが、δ = ±0.5% の線形の運動 (1 μm) で D が −5.8〜−7.2 までしか下がらず (NAFF の周波数に 1e-6 の系統誤差)、**標本の 2 次のモーメントから楕円の α・β を求める**ことにした (`norm='data'`、D が −9.6〜−11)。`norm='twiss'` も残した |
| 二分法 | 粗い走査 (ncoarse 点 + Δ = 0) で最初に失われた点を挟んでから、nsub 点ずつの k 分割 (nsub = 1 は二分法)。1 つの追跡の束に位置の ± 両方の点を入れる (粒子数にほぼ比例する時間でも、Python の呼び出しの回数が減る) |
| Touschek | `TouschekTable` の `table[3]` (要素ごとの損失率 × 120 点の一様な受容 dp) から。対称な a の損失率は +Δ・−Δ の両方の粒子を数えるので、片側ずつ半分の和。要素ごとの受容は中央の s の線形補間 (周期的に折り返せる)。既存の `touschek.py` は変えていない |
| 台本の関数 | `FrequencyMap[]`・`MomentumAcceptance[]`・`TouschekLifetimeLMA[]`。オプションは SAD の流儀 (`Rule`、大文字小文字を区別しない)。戻りは `Rule` のリスト (`Diffusion /. f`) |

### 2.3 K64 の新しい誤りの候補 (B 番号を付けるもの)

なし。気づいた K64 の癖 (誤りではなく仕様):
- `TrackParticles` の tapert の判定の位置は、区間の始めから数えるので、`TrackParticles[{loc, beam}, loc, 1, n]` (1 回の呼び出し) と n 回の 1 周ずつの呼び出しで、損失ぎりぎりの粒子の判定が違う。
  アパーチャが限界のとき δ の限界が 1.2〜1.3 倍違う (ASTRID2 の例)。K64 の仕様 (docs/11_sad_quirks.md の候補)。

## 4. 要判断・未確認・限界

- **互換モードは v2 でだけ確かめた (k64 は未確認)。**
- **誤差・結合のあるリング、FLUC つきの LMA、PF リング、挿入光源つきのリング (`ASTRID2_v01_02_id.sad`) は確かめていない。**
- 二分法は外向きの最初の損失を限界とする (走査の点のあいだの狭い損失の窓と、その外側の島は見ない)。
- RF バケットの判定は |z| の限界 (π + 2|φs|)/k_rf で、バケット高さの付近の限界は周回数に依存する。独立な計算 (Hamiltonian の分離線との比較) はしていない。
- 周波数マップの D の下限は NAFF の精度と規格化で決まる (線形の運動で −9.6〜−11)。共鳴線の上のロックした点は D が小さい。nturn が短いと下限が上がる。結合が強いと νx・νy の対応が崩れる。
- 1 セルの結果を全周に延ばす (Touschek) のは、空洞が 1 か所であること・閉軌道の δ の違いを無視する (差は例で tol〜3 tol)。
- 例の LMA の大きなリング A は、±10 mm のアパーチャでは RF バケットで決まる (分散が小さい)。アパーチャで決まる例は ASTRID2 だけ。
- 周波数マップの統計 (共鳴線の近く/遠くの D > −5 の割合の比 2 倍) は弱い。個々の線の駆動の強さの確認は Q2 (`docs/49_resonance_terms_adts.md`) の仕事。
- 損失の判定の位置は要素の境界。要素の中の損失は見ない。`check_every` で細かくしても、BEND・QUAD の中は判定しない。
- 計算の時間: ASTRID2 の LMA 25 位置 364 s (2 並列)、大きなリング A の LMA 43 位置 580 s (2 並列)、周波数マップ 1271 点 305〜315 s (1 プロセス)。
