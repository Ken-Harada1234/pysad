## 4. 既知の原因 (乱数消費のずれ)

(2026-10-16 追記: §4 末尾の (a)/(b) の切り分けは `work_loss_rng2.md` で済んだ。(a) 別の要素での発散は再同期テストで見つからず、論理の違い 3 件 (rot1、g の NaN、xsincos) を直した。主因は (b) の丸め誤差のカオス的な増幅。再実行の結果は §6。)

RAD+FLUC は光子放出の乱数列に依存するため、乱数の消費数が 1 つでもずれると以降の粒子の軌道は統計的にしか一致しない。
`docs/history/work_loss_rng.md` に、粒子が落ちる周の乱数消費のずれ (track6n の sqrt1/pxy2dpz の NaN、tapert の la の数え方、
asinz(NaN)、norm2 の ±inf) を直した記録がある。その修正で bench_level16l の 12 ケースは最終 seed まで一致した。
しかし本ベンチの最終 seed は一致していない (full: SAD 1343530601 / pysad 2192765257、small: 966470477 / 3112541665)。
つまり (a) 損失の経路が 16l の網羅した 3 例以外 (別の要素での発散、tradkfn 以外の NaN 経路) にも存在する、
または (b) 損失の無い周でも微小な乱数/浮動小数点の差があり、カオス的な粒子 (地図の端の粒子) で増幅されて別の損失周になる、のどちらかが残っている。
-43.18 行の idx0 (SAD 970 周) のように 1000 周近い長寿命粒子の生死が分かれるのは、境界付近でのこの増幅と整合する。
どちらが主因かは、この材料だけでは切り分けていない。切り分けるには、small (100 周) で粒子ごとの seed を SAD と突き合わせて最初にずれる要素を探す手順 (j22 と同じ方法) が必要。
