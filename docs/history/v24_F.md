# v2.4.0 F: ROTATE した偏向磁石の RDT・ADTS、DA 関係の v2 の既定の見直し (2026-11-22)

担当 F (resdrive・ampnf・touschek*・lma*・dapert・ffscmd の DA 関係)。方針 (ユーザー指示): v2 以降は誤りを指摘した上で v2 モードで直す。k64 は不変。独立な基準で確かめられるものだけ直す。解析式を追跡に合わせる補正は足さない。

## F1: ROTATE した偏向磁石 (最優先)

### 何を変えたか

- `ampnf.py`: ROTATE・ROTATION のある BEND・QUAD・SEXT・OCT を、回転 R (素子座標 = R · 実験室座標。K64 の `tchge` と同じ向き。pysad の追跡のヤコビ行列と 2e-15) ・傾けない素子・R⁻¹ に展開 (`_expand_rolls`)。傾けない座標で線形 (垂直分散つきの δ の級数)・曲率・端・運動学・フリンジを作るので θ の全次数が入る。1 周の線形写像が結合していたら 4×4 の固有モード (`linear_modes`: ē^T S e = 2i の規格化、x/y のモードは横成分の大小で割り当て、位相は x 成分・y 成分が実で正) で正規形を作る。結合がなければ従来の Twiss の式 (出力は従来と同一)。`nf_action`・`initial_from_nf`・`model_tune` もモード正規化に一般化 (`res['Amat']`・`res['Ainv']`)。
- `ampnf.rdt_series`: 1 周の写像の 2 次の部分から h_jklmp (3 次 20 項、δ の項 9 個)。`rdttrack` と同じ手順で、結合したモードの正規化でも動く。`rdttrack.normalizing_matrix` は 4×4 行列を渡すとそれを A として使う。
- `ampnf.tracked_tunes`・`tracked_adts`: pysad の実際の追跡 + NAFF の検証用 (振幅 0 の面の NAFF は雑音を拾うので、両方の面に振幅のある 8 点でフィット)。
- `resdrive.py`: `rolled_elements`・`unrolled_lattice`。`resonance_terms` は傾いた (ANGLE・K1・K0≠0 の BEND、K1≠0 の QUAD に傾き) 素子があれば結合した光学の経路 (`coupled=None`)。`adts` は `rolls=None` で、ロールを外した lat の解析式 + ampnf (D=3) の J¹ の差 `.rotate` (`.total` に入る)。ampnf が扱えない素子 (K0≠0 の磁石など) があれば従来の式 (傾いた素子は飛ばす) + 警告。台本 `AmplitudeTuneShift[]` は `Rotate->` を返す。
- 見つけた不具合 (pysad 自身): ampnf は SEXT・OCT の ROTATION (パーサは ROTATE を ROTATION に入れる) を黙って無視していた。ANGLE=0・K0=0 の傾いた BEND (ASTRID2 の PV 12 台) は傾きが効かないので数えない。

### 検証

`test_v24_F1_rotated_bend.py` (7 件)、`example/v2_4/F1_fodo.out.txt`・`F1_astrid.out.txt` (`F1_rotated_bend.py`)。数値は docs/49 §14.2。要点:

- FODO・1 台を 50 mrad 傾ける: 同じ模型の追跡 3e-8、実際の追跡 3e-6、追跡の写像の 2 次のテイラー展開から取り出した h が 6e-4 (ロールなしと同じ水準)。
- 全 24 台を 0.1 rad 傾ける: `adts().total` が実際の追跡のフィットと 1.5e-3 (傾きの分を入れないと xx で 2.3e-3、xy で 3.8e-3)。θ = 0.3 では傾きの分が 2〜3%。
- ROTATE = π = 逆曲げ (ANGLE を負にする。SAD の E1・E2 は曲げの向きに対する相対): 模型の ν0・J¹・ξ が 1e-9、`adts().total` が ANGLE < 0 の解析式と 1e-3 (傾きの分 yy +8.5 が 1.6%)。
- 摂動の次数: スキューの h は θ の 1 次 (比 2.00)、ADTS の傾きの分は θ² (比 3.7〜4.3)。ADTS は θ → −θ・y → −y の鏡映で不変。
- ASTRID2 (0.58 GeV) の全 BEND を 20 mrad 傾ける (結合 0.068): 傾きの分を入れない ADTS は追跡と 1.2〜2.8%、入れると 0.014〜0.23%。

### 範囲・未確認 (docs/49 §14.3・§14.4)

K0≠0 の磁石に ROTATE がある場合は未対応 (ampnf が K0≠0 の磁石を扱えない: 磁石の中の軌道のまわりの展開が要る。次の手は、`bendnl.orbit_decomposition` の要素ごとの写像を軌道のまわりの 3 次まで取り出して TPSA に渡す)。結合した経路の 4 次の h・δ≠0・DX/DY は未対応。E1・E2≠0 と K0≠0、ANGLE≠0 かつ K0≠0 は A2 で確認済み (傾き無し)。MPW・逆曲げの実機規模: MPW (K0≠0) の傾きは未対応、逆曲げ (ROTATE = π) は上のとおり。

## F2: v2 の既定の見直し

1. **B200 Touschek のバンチ内の δ の分布**: v2 の `TouschekLifetimeLMA[]`・`TouschekLifetime[INF, INF, nz]` (Piwinski 型)・`lma.touschek_lifetime_local_piwinski` の既定を BunchDelta・BunchQs つきに (`->False` で切る。k64 は従来)。`touschek_piwinski_bunch(qs=True)` は ASTRID2 全周で数十秒。`test_v23_T2_touschek.py` の v2 の既定の試験は `BunchDelta->0` を明示する形に変更。
2. **B201 DAS の `ExpandElementValues` の既定**: v2 は False (k64 は True)。
3. **WSPACSC**: 据え置き。`WSPACSC = 1` の行列は MINCOUP の下限で垂直のビームサイズを人為的に大きくする (B149 の例で垂直のチューンシフトが 1/3)。解析式の空間電荷チューンシフトはビームの大きさを与えたときの式で、どちらの行列が実際のビームかは決められない (どちらも一次の式と 2e-4)。独立な基準の gs の追跡はゼロ電流の行列と 1〜2% で合う。
4. **LMA の補正後の状態を TrackSetup に渡す経路**: FrequencyMap・MomentumAcceptance・NormalFormTune は TrackSetup を作る前に CALEXP に依らず `spread_pending` を呼んでいた (pysad 自身の不具合)。NOCALEXP の台本なら成分ごとの値を保つように直した (`test_v24_F2_defaults.py`)。KEK-LS の誤差つきの LMA の実走は未実施。ASTRID2 の SynchroBeta の追跡は指示により対象外。
