# v2next の記録: 担当 B2 (SADScript・関数・FFS の小項目の未対応の追求、2026-11-18)

v2.0.0 の記録 `v2_changes_B.md`・`v2_changes_C2_misc.md` の「要判断・直さなかったもの」と `docs/46` の SADScript・特殊関数の項のうち、B2 の 8 項目を実装し確かめた。
gs は SAD K64 (1.4.4.2k64、2026-10-19 ビルド、WSL)。`docs/46`・`docs/47`・README・CHANGELOG は触っていない。

- 互換モード: 「k64 モード」の欄が「同じ」の項目は、pysad が gs と違っていた (pysad 自身の不具合・未対応) ので、モードで分けずに gs に合わせた。
  K64 自身の誤りで gs と違う値が真値のもの (Union の SameTest、WriteBeamLine の Name、Begin の文字列) は `if compat.v2()` で分け、k64 は gs と同じ。
- 根拠: 数値は独立な計算 (mpmath は無い。Borwein の交代級数、別に書いた Euler–Maclaurin、scipy.special.spence、積分表示の数値積分、漸近展開、接続公式、閉じた式)。
  FFS・文脈・Packages の関数は、同じ台本を gs と pysad (k64) で走らせて、出力を行ごとに突き合わせた。
- 試験: `pysad/tests/test_v2_B2_script.py` (16 件、Windows では 1 件 skip・POSIX では別の 1 件 skip)、`test_v2_B2_free.py` (6 件)、`test_v2_B2_specfn_cx.py` (8 件)。計 30 件。
- 走る例: `example/v2_next/B2_*.sad` (台本)、`.gs.txt` (gs)、`.pysad.txt` (v2)、`.pysad_k64.txt` (k64)、`B2_parallelize.pysad_wsl.txt` (WSL の fork)。
- 大きなリングでの確認: 成分ごとの FREE は大きなリング A (`kek-ls_v03_12.lat`、3 GeV、周長 603 m、3563 要素) で gs と比べた (下の項目 1)。
  文脈・Message・Symbol・複素の特殊関数・Parallelize はリングに依らない (小さな試験用の台本)。

## 2. 補足

### 2.1 FREE の実装 (`ffscmd.py`)
`_freefix` が語の `.` を見て `_free_components` へ。変数は `dict(family, key, els=[成分], comp=位置, label='B.3', …)`。`FFS.set_var(v, val)` が成分の変数はその成分だけ、ほかは `set_family`。
`_sort_vars` が要素の順 + 後から FREE したものが先。`FFS._tfvcomp` は `comp` つきの変数があれば真 (成分の変数は既定でないキーだけ作るので、K64 の定義と同じ)。
`_fix_vars` が FIX の規則。VAR の Couple の欄は既定のキーだけ `<--` (gs)、制限値は既定のキー ±1e10、ほかは ±1e99 (gs)。`match6.py`・`match6d.py` は変えていない (変数が持つ `els` で微分する)。
なお `Element["K1","QF"]+=0.1`・`LINE["K1","QF"]+=…` (複合代入) が、`Element`・`LINE` のフックを通らずに利用者の規則を作っていた pysad の不具合を直した (`sadscript.py` の `_opassign`・`_inc` が包み直した `Set` を呼ぶ)。

### 2.2 `specfn_cx.py` の精度の範囲 (§1 (2) の根拠の続き)
`hurwitz_c`: N = 20 + \|s\|/1.5 + \|Im a\|/2 項と補正 16 項。\|s\| = 100 で相対 1e-11 (Borwein は n = 60 で \|Im s\| = 100 で足りず、Euler–Maclaurin N = 300 と比べた)。
`polylog_c`: μ の展開は 110 項まで。倍角の再帰は \|z\| = 1e8 で 5 段。`hyperu_c`: 積分は被積分関数の山 (\|z\|⁻¹ 付近) で区間を分け、a < 1 は t = u^{1/a} で端点の特異性を除く。
gs の誤りの範囲は 230 点の乱数と 26 点の格子で調べた (表のとおり)。k64 でも真値を返す。

### 2.3 Parallelize の実装 (`fileops.py`)
子は `os.fork` で f[k] を計算し、結果を `enc` (Shared と同じ符号化) して一時ファイルに書き `_exit_child`。親は `waitpid` で回収し、npara を超えないように待つ。子の異常終了は `$Failed`。
子の `Print` は親と同じ出力先 (出力先が Python の StringIO のときは親に届かない: Fork と同じ)。npara = 1・n = 1 は逐次 (fork しない)。

### 2.4 gs の `a/b` は `a*(1/b)` (最後の桁)
`Log[100]/Log[10]` は gs が 1.9999999999999998、pysad は 2 (直接の割り算)。K64 の除算は逆数の積なので、最後の桁が違う (`Log2$` はこれに合わせた)。
評価器全体の除算は変えていない (1e-16 の雑音で、変えると全試験の基準値に影響するため)。要判断。

## 4. 要判断・直さなかったもの

| 項目 | 判断 | 理由・調べたこと |
|---|---|---|
| 複素の特殊関数で gs が誤る点の k64 の値 | 真値を返す (gs の誤った値は再現しない) | 再現には gamma.f の複素の不完全ガンマ (`cgamma2`)・`czconvb`・`cpolylogl` の直訳が要る。誤りの範囲 (§1 (2)) は記録した。gs の値が必要なら gs を使う |
