## gs との差 (未解明、要判断) — **解決済み: 原因は gs の台本の RFSW ON (空洞の δ)。`NORFSW;` で一致。`docs/history/v23_R1.md`。以下は Q2 の時点の記述**

- FODO では gs の C が pysad・解析と全部一致。ASTRID2 と大きなリング A では、**6 極の強さを ×1 にした全部入りの gs は pysad (k64) と一致するが、×0・×−1 の gs の ADTS が pysad (k64) と違う**。
  大きなリング A の 6 極・8 極を 0 にした gs の ADTS = (35320, 30503, 25972)、pysad (k64) = (877, 2074, 2485)。gs と pysad の 1 周目の座標は 1e-8 (相対)、チューンは 1.1e-5 違う (K2 は gs の `LINE["K2","*"]` で全部 0 を確認)。
  原因の候補: 複合機能の偏向磁石 (K1) の非線形の扱い、または gs の一周の座標に空洞の影響が残る。確かめていない。解析式の検証には、gs の差が出ない FODO の gs と、pysad の追跡を使った。
- 追跡の落とし穴 (K64 の誤りの候補、B 番号は付けない): gs の TrackParticles は RFSW OFF でも `z` を返す。それを次の周の入力に戻すと空洞 (RF あり) が z に応じた δ を与える。z を毎周 0 にすると pysad の `rfsw=False` の追跡と一致 (FODO で 1e-6)。
- gs の FFS で `SDA K2 値;` は、同じ名前の要素を MAIN で何度も再定義したラティス (大きなリング A、ASTRID2 の末尾) では効き方を確認していない (文字列で K2 を書き換える方法を使った)。`gsrun.sh` は一時フォルダに basename でコピーするので、同時に 2 本走らせると同じ名前のスクリプトを上書きして結果が混ざる (一度これで誤った値を得た。`Q2_adts_gs.py` は一意な名前を使う)。

## 使える範囲・使えない範囲 (docs/49 §5 の要約)

使える: 誤差なしの設計ラティス、結合なし、δ = 0 (または CALC のオフモメンタム光学)、SEXT・OCT・MULT (K2・K3・SK・ROTATE、K1 つきの厚い MULT)、厚い・薄い。
使えない・入れていない: 結合、垂直分散、DX・DY のある素子 (警告)、偏向磁石・四極の端部と運動学的な項の非線形 (追跡には入る)、6 極×8 極と 8 極 2 次、10 極以上、MULT の K0・ANGLE の内部の光学、∂²ν/∂δ² の解析式、共鳴線の近傍の追跡の応答、文献の h_jklm の符号・規格化との照合。
