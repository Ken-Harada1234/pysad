01. pysad の全体像と文書の案内

pysad は、加速器コード SAD (K64 版) の計算 (光学・エミッタンス・マッチング・粒子追跡・ダイナミックアパーチャ) を Python で再現し、SAD の台本をそのまま動かせるようにしたものである。

  • この文書で分かること: pysad が何を計算できるか、SAD のどの部分がどのモジュールに対応するか、動かし方、どの目的のときにどの文書を読めばよいか (全 36 本の目次)。
  • 前提: 加速器物理 (光学・エミッタンス・追跡) の基本を知っていること。SAD と pysad は知らなくてよい。
  • 読む順: まず §1・§2 (目的と文書の選び方)、§3 (動かしてみる)。SAD のしくみは §4、pysad のモジュールの対応は §5。全体の目次は §8。
  • 用語: SAD = KEK の K. Oide らの加速器設計コード。K64 = その GitHub 版 (https://github.com/KatsOide/SAD)。gs = K64 の実行ファイル。MAIN 部 = 要素と LINE を定義する層。FFS = SAD の対話・台本の層 (FFS; 以降)。SADScript = SAD の台本言語。v2 モード / k64 モード = pysad の 2 つの動作 (§1)。

場所: コードは <repo>\ (pysad 本体は pysad\、文書は docs\、図つきの HTML は docs\html\)。 対象の SAD は KEK 本流ではなく K64 版。コマンド・要素キーワードの意味は CERN の SADHelp (https://hep-project-sad.web.cern.ch/SADHelp/SADHelp.html、1.4.0.0k64 2025-07-14) か、ローカルの <SAD>\Documents\SADHelp.html (1.4.4.2k64 2026-10-19、使っている WSL ビルドと同じ版) を先に見る。KEK 公式サイト (acc-physics.kek.jp) は別系統の SAD なので参照しない。数値の最終根拠はローカルのソース <SAD>\src と Packages\。

1. 目的と方針

  • 目的: SAD の光学計算・エミッタンス・マッチング・粒子追跡・DA を Python で計算し、SAD スクリプトを run_sad.py でそのまま動かす。
  • 2 つの動作モード (互換モード pysad/compat.py):
    • v2 モード (既定): K64 のバグ・物理の誤りを直し、機能を足した動作。利用者はふつうこちらを使う。
    • k64 モード: K64 に忠実な翻訳 (SAD の Fortran の式・分割数・反復順序・乱数の引き方を写し、バグに見える癖も再現する)。PYSAD_COMPAT=k64 か pysad.compat.set_mode('k64') で切り替える。gs と数値を比べるときはこちら。既存の試験と回帰は k64 で走る。
    • 2 つの違いは 28_v2_vs_k64.md、K64 自身のバグ目録は 30_sad_bug_report.md、SAD の癖は 29_sad_quirks.md。
  • k64 モードの基準: 1e-10 以下の差、表示の桁、丸めカオス後の乱数 seed は追わない。「計算が完走し、物理量が SAD と有意に一致する」ことを基準にする。
  • 翻訳の範囲: Fortran/C の物理計算は直接翻訳する。Packages/*.n は SADScript のまま pysad のインタプリタで実行するか、Python で書き直す。ファイル・リスト・GUI・描画は Python のライブラリで代替し翻訳しない (36_sadhelp_purpose_policy.md)。
  • 実行環境: Python 3.12 (py -3.12) に numba / scipy / pytest。PYTHONIOENCODING=utf-8。参照値 (gs) は WSL Ubuntu の bin/gs で取る (NPARA=1; を入れる)。長い計算は優先度を下げて 1 本ずつ流す。
  • 対象外: EPICS、Python ブリッジ (SAD 側の PySad.c は非コンパイル)。System[] は既定で実行しない (環境変数 PYSAD_ALLOW_SYSTEM=1 で許可。05_sadscript.md)。Tcl/Tk の GUI と描画 (ListPlot・Plot・OpticsPlot など) は、SAD 自身の Packages/*.n を pysad のインタプリタで解釈して tkinter に表示する方式で対応している (20_tcltk_gui.md、21_graphics.md)。見た目 (色・大きさ・フォント)・操作の動作は SAD と比べておらず、Canvas3D* は未対応。既知の差: 最初の Window[] の親が、gs では Toplevel、pysad ではルート窓。Options[g] は gs が全オプションを返し、pysad は {}。OpticsPlot の text 項目数は Tk のフォントによる RemoveOverlap の差で違う。w=Window[]・e=Entry[w] は Widget[…] 値になり、e[Insert]・e[Get]・e[Delete] は gs と同じく働く。
  • 扱う要素: DRIFT / BEND / QUAD / SEXT / OCT / DECA / DODECA / MULT (ANGLE≠0 を含む) / SOL / CAVI / TCAVI / UND / COORD / MAP / BEAMBEAM / MARK / MONI / APERT / INS。PHSROT は K64 で動作しない (行列が 0、B38) ため、k64 モードでは追跡が NotImplementedError、v2 モードは意図された写像を実装した (10_tracking.md §9.7)。SPCH は K64 の tturn.f:521 の case (icSPCH) が PSPAC フラグのとき tpspac (粒子のメッシュによる空間電荷) を呼ぶ要素で、v2 モードでは SPAC・PSPAC・WSPAC が TrackParticles に入る (k64 モードは入らない)。PROF は K64 のソースに現れず、parser が読むだけ。要素別の状況は 19_other_elements.md ほか各文書。
  • 未対応・未確認の唯一の一覧は 31_unimplemented_and_unverified.md。

3. 動かしてみる

手順 (<repo> の直下で実行):

  1. (任意) 最初の実行は、計算の核 (numba のカーネル) を機械語に変換するため約 1 分かかる (2 回目以降は 1〜2 秒)。先に済ませるには pysad-warmup を 1 回実行する (pip で入れたときのコマンド。リポジトリからは py -3.12 -m pysad.warmup)。--check で有効か確認、--clear で消す。

  2. SAD の台本を実行する。ラティスの台本と計算の台本を続けて渡す (SAD の gs に複数ファイルを連結して渡すのと同じ)。

cd "<repo>" set PYSAD_SAD_PACKAGES=<SAD の Packages のフォルダ> py -3.12 run_sad.py example/00_lattice/FODO_ring.sad example/02_optics_cod/FFS_CALCULATE.sad

24 セルの FODO リング (3 GeV、周長 105.6 m) の最後に NX= 6.696329 NY= 4.906056 と出る。これは水平・垂直のチューン (νx, νy) = (6.696, 4.906) である。PYSAD_SAD_PACKAGES は SAD 自身の Packages/*.n (CorrectOrbit・GUI など) を使うときに要る。 2. Python から使う (詳細は 12_pysad_api.md)。

python from pysad.parser import load_sad_file # → SADScript (env に Lattice と LINE) lat.twiss_table(delta=0.0) # CELL CALC (qcell1)。lat は Lattice from pysad.emit6d import emittance6d; emittance6d(lat, 3e9, rfsw=True, radcod=False) from pysad.match6 import Matcher; m = Matcher(lat); m.fit('NX', 47.6); m.free('Q*'); m.go() from pysad.track6n import track_particles_fast # TrackParticles の本体 from pysad.dapert import dynamic_aperture # DynamicApertureSurvey の本体 3. 試験と回帰を走らせる (§7)。 4. gs で参照値を取る (WSL Ubuntu): MSYS_NO_PATHCONV=1 wsl -d Ubuntu -- <SAD>/bin/gs file.sad > file.result (台本に NPARA=1; を入れる)。

4. SAD の構造

SAD は MAIN 層 → FFS 層 → SADScript 層の 3 層で、計算本体は FFS から呼ばれる。pysad も同じ層に分けて対応させている。

MAIN 層 (toplvl.f)   要素定義 / LINE / 数値代入 / FFS, TRACK, EMIT の起動。SADScript は使えない
   └ FFS USE=…;  → track.f (tfinitn で SADScript 初期化、RFSW=ON, CALC6D=OFF 強制) → tffs → tffsa (コマンドループ)
        FFS 層 (tffsa.f)  1 語の解釈順: tfprint (式に見える語は SADScript として評価) → tflag (フラグ) → tgetfv (FIT 条件) → terror (誤差) → tffile → 要素名 (tfgetlineps→tfgetv) → コマンド群 → tfgetv (要素値、失敗なら ?Undefined command) (詳細は 03_ffs_commands.md §1)
        SADScript 層      tfetok (字句) / tfeval (構文、優先順位は tfstk.f iprior) / tfefun* (組み込み関数)、Packages/*.n
物理計算   CAL/GO: tffsmatch → tffscalc → qcell1 (qcod → qmdiag → qtwiss)
           Emittance[]: emit.n → temit → tturne (tquade/tbende/tthine/tcave + tradke) → tecalc
           TrackParticles[]: tftrack → tturn → tturn1 (tdrift/tquad/tthin/tbend/tcav/tmulti/tsol + tradk)
           DynamicApertureSurvey: dapert.n → tfdapert → trackd → tturn

次の表は、SAD の計算で中心になるソースファイルと役割である (ソースを読むときの索引。構造の詳細は 32_source_analysis.md、翻訳状況は 33_fortran_status.md)。

7. 性能と試験

性能 (2026-11-06 の測定値。再測定していない):

  • 1 回の cell calc 0.03 s (不変時) / 0.145 s (変更後)、Twiss[] 0.6 ms、追跡 176 ns/粒子・要素 (numba)。
  • 600 s 内に終わらない計算: 誤差入り 6D emit × 多数の実現 (300 実現 221 s、SAD 37 s)、DA の 5000 周 × 969 粒子 (約 50 分、SAD も 300 s 超)。残る改善点は 6D の tturne 1 周 (0.03 s) と DA 系。

試験とベンチ:

  • テストは pysad/tests/ (test_*.py)。2026-11-21 の通しは、収集 1907 件、1899 通過・8 skip・失敗 0 (その時点で test_*.py は 158 ファイルだった。以後ファイルが増えており、現在の件数は未再確認)。v2 の試験は test_v2_*.py (73 ファイル・1081 件) で compat.set_mode('v2') を明示する。その他は gs との比較なので k64 モードで走る (conftest.py)。
  • 実行:

py -3.12 -m pytest pysad/tests -q --ignore=pysad/tests/script_tests/test_bend_feeddown.py --ignore=pysad/tests/script_tests/test_coord.py --ignore=pysad/tests/script_tests/test_sext_radiation.py QUICK=1 py -3.12 -u pysad/tests/regression_tests/run_regression.py

--ignore する 3 本 (test_bend_feeddown.py・test_coord.py・test_sext_radiation.py) は sys.exit で終わる旧式のスクリプト。環境変数 PYSAD_SAD_PACKAGES=<SAD の Packages のフォルダ> が無いと GUI 系は skip。PYSAD_SLOW=1 で遅い試験 (CSR の MakeZL、約 7 分) も走る。GUI 系 (test_plot・test_tclbridge) は全体実行で数回に 1 回失敗することがある (単独なら通る)。 - 回帰 pysad/tests/regression_tests/run_regression.py (k64 モード。説明は pysad/tests/regression_tests/README.md) は 50 ベンチ。QUICK=1 は遅い 4 件 (7・12t・13a・16a) を SKIP して 46 件を実行する。2026-11-18 の QUICK=1 の通しは FAIL 0。QUICK なしの全 50 ベンチ (205 s) の記録は 2026-11-16 夜 (local/wake/verify_log.md)。 - ベンチ: pysad/tests/regression_tests/bench/ (自動判定の対象外は bench_extra/) の bench_level1〜31*.sad/.result (gs の出力) と *_pysad.py/.result。結果の一覧と一致度は 27_benchmarks.md。 - 試験が走らせる SAD スクリプトと gs・pysad の画面表示は pysad/tests/script_tests/scripts/ (NAME.sad・NAME.gs.txt・NAME.pysad.txt)、試験関数との対応は pysad/tests/script_tests/OUTPUTS.md。
