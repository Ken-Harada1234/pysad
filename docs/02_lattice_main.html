02. SAD の MAIN レベル (ラティス定義) と pysad の parser

この文書で分かること: SAD の入力ファイルの前半 (MAIN レベル: 要素の定義、LINE、MOMENTUM= などの変数) がどう読まれるか、要素型ごとのキーワードと単位、pysad の parser がそれをどう Python の要素に変換するか。 前提: SAD のラティス (QUAD QF=(L=0.25 K1=1.0); のような書き方) を見たことがあること。FFS (対話コマンド) の部分は 03_ffs_commands.md と 04_ffs_small_commands.md。 読む順: 初めての人は §1 (入力の構造) → §4 (動く例) → 必要になったら §2 (キーワード表)・§3 (parser の変換)。

用語: MAIN レベル = FFS; より前の、要素・LINE・変数を定義する部分。FFS = その後の対話コマンド層。K64 = 本プロジェクトが翻訳の元にした SAD (Fortran) のビルド。gs = その実行ファイル。

照合対象: <SAD>\src (K64 版 SAD, Fortran) と pysad/parser.py。SAD ソースの行番号は 2026-10 時点。 表記: 無印 = コードで確認した事実 / 「解釈」= 推論 / 「未検証」= 未確認。parser.py は改訂が続くため行番号ではなく関数名で示す。

1. SAD 入力ファイルの構造 (MAIN レベル)

1.1 トップレベルの読み取り (toplvl.f: toplvl)

gs file.sad で起動した SAD は MAIN.f → initbl.f (コマンド表) → initb1.f (要素型・キーワード・単位・グローバル変数の表) を経て toplvl に入り、トークン単位で次のように振り分ける (toplvl.f:1700-1760)。

トークン 種別 (idtype) 処理
DRIFT, BEND, QUAD, … icDEF (< icMXEL) doelem — 要素定義ブロック (doelem.f)
LINE / CELL icDEF (icLINE=100) doline — ライン定義ブロック (doline.f, lread.f)
FFS, TRACK, EMIT, QUICK, LIE, PLOT icACT doACT → ActTra (track.f) など。FFS; 以降は FFS コマンド層 (tffsa.f)
ON / OFF / READ / PRINT / STOP / EXPAND / REVERSE / LIST sethtbr 登録のサブルーチン (initbl.f) doonfl/dooffl (doflag.f), doread, dostop など
既存の要素名 / LINE 名 1..icMXEL / icLINE doelm2 / dolin2 — 型キーワードなしの再定義
それ以外の識別子 — dAssgn (dAssgn.f): NAME = 式; でグローバル実数 (icGLR) を定義・代入
;, }, CR — 読み飛ばし
  • ! から行末まではコメント (gettok.f:55 if (curc == '!') call myfflush)。文の区切りは ;、ブロックは { } でも囲める (doelem/doline は { を任意で受ける)。
  • FFS; で ActTra に入り、FFS 内の STOP/END で MAIN に戻る。MAIN の STOP; (dostop) で SAD が終了する (bench_level12.result 末尾の *** dostop *** Good Bye!)。
  • 初期の MOMENTUM は 30 GeV (initb1.f の RsetGL('MOMENTUM',30.d9)。pysad も ffscmd で同じ既定)。MAIN で MOMENTUM= を書かない台本は FFS の USE 以後も 30 GeV で計算される。
  • gs の慣習: ラティスファイル (MAIN 部のみ) と FFS スクリプトを連結して 1 本の .sad として bin/gs に渡す。本プロジェクトでは bench_level12.sad = <試験用ラティス>.lat + FFS 部であり、pysad 側は load_sad_files(lat, script) / run_sad.py lattice script が同じ連結を行う (docs/history/00_RESUME.md Level 14)。

1.2 MOMENTUM=, グローバル変数, 式と単位

  • MOMENTUM = 3GEV; は dAssgn → rdterm → yyparse (calc.y) で評価される。文法は NUM UNIT → $1*$2 (calc.y:65)、演算子 + - * / ^、関数 SIN COS TAN ATAN ATAN2 SINH COSH TANH SQRT EXP LOG LN (yylex_.c:25-38)。
  • 単位表 (initb1.f:1618-1670, icUNIT): %=0.01, RAD=1, MRAD=1e-3, DEG=π/180, M=1, CM=1e-2, MM=1e-3, T=1, GAUSS=1e-4, JOULE=1/e, EV/KEV/MEV/GEV=1/1e3/1e6/1e9, V/KV/MV/GV, HZ/KHZ/MHZ/GHZ。大文字小文字の両方が登録されている。
  • 既定のグローバル (initb1.f:1697-1790, defglb+RsetGL): MOMENTUM=30e9 (既定 30 GeV), MASS=電子質量, CHARGE=0, PBUNCH=1e10, NBUNCH=1, EMITX/Y/Z=0, SIGE, SIGZ, FSHIFT=0, DP… など。
  • 式の中の識別子が icGLR のグローバルなら値に置き換わる (yylex_.c:93-96)。したがって QFK1=1.2; QUAD QF=(K1=QFK1); のように要素パラメータに変数を使える。

1.3 ON/OFF 行 (doflag.f)

ON ECHO; OFF LOG; は $ECHO$, $LOG$ という整数フラグ (icFLAG) に FLAGON/FLAGOF を入れる。未定義の名前は新規フラグとして定義され "New flag … is defined." と表示される (doflag.f:36-48)。MAIN の $RAD$ $FLUC$ $COD$ $RADCOD$ $INTRA$ $POL$ $DAPERT$ $EMIOUT$ … は FFS 入口 (track.f:80-107、IgetGL('$RAD$') 等) で FFS のフラグに写される (実測: OFF RAD FLUC COD RFSW RADCOD; で RAD/FLUC/COD/RADCOD が F)。$RFSW$ だけは届かない: isynch=IgetGL('$RFSW$') を読んだ後、FFS に入るとき rfsw=.true. に固定される (track.f:149)。FFS 入口の表 RFSW RADCOD RAD … の RFSW 列は $RFSW$ の値 (既定 F) で、FFS の FLAG[{"RFSW"}] は 1。pysad: run_sad_string/main_exec は RFSW を main_flags (MAIN の TRACK 用) に入れ、FFS の RFSW は ON のまま (docs/history/work_zdp.md)。既定で ON の MAIN フラグは FLUC と COD。

1.4 要素定義 (doelem.f, rdkwdl.f, rdexpr.f)

QUAD   QFA1 =(L =.25  K1 =1.0302859090451 )
       QFA1H=(L =.125 K1 =1.0302859090451/2 )
 ;
  • TYPE name=(kw=式 kw=式 …) name2=(…) … ; — 名前はいくつでも続けられ、区切りは空白または ,。
  • 新しい名前: idtype=型, idval=ktcaloc(kwMAX+1) (doelem.f:43-48)。ktcaloc はゼロクリアするので (italoc.f:86-94) 書かなかったキーワードは 0。
  • キーワードは CAPITA で大文字化 (rdkwdl.f:40) し、icKWRD かつその型で有効 (kytbl(kw,型)≠0) でなければ "invalid key word name" / "Undefined keyword" でエラー (rdkwdl.f:43-66)。値は rdexpr → yyparse なので L=.413/2, K3=-6000*0.0125, ROTATE=-90 DEG のような式が書ける。
  • 再定義 (後勝ち): 同じ型で同じ名前を再定義すると同じ格納領域に rdkwdl を再実行する (doelem.f:57-60)。つまり 書いたキーワードだけが上書きされ、書かなかったキーワードは前の値を保持する。別の型で再定義すると "already used as …" エラー (doelem.f:61-66)。
  • 要素の値が LINE 展開にコピーされるのは USE 時 (§1.5) なので、LINE を書いた後で要素を再定義しても反映される (<試験用ラティス>.lat は LINE の後に BEND/QUAD/SEXT を 3 回再定義しており、最後の値が有効)。

1.5 LINE 定義と展開 (doline.f, lread.f, expln.f)

LINE  ARCA = (ARCAH -ARCAH2)
      RING = (MKS ARCA, ARCA, … RFC, ARCA … MKE)
 ;
  • lread が項目ごとに多重度 mult と名前を積む: - で mult=-mult、N* で mult=mult*N (lread.f:36-71)。したがって -ARCAH2 は逆順、2*SDA は 2 回、-2*X は逆順 2 回。+ は無視。項目は要素名でも LINE 名でもよく (入れ子)、定義時点で未定義の名前も許される (展開時に "is not defined yet" 警告, expln.f:110-116)。
  • LINE の再定義は "… is redefined" の通知 (レベル −1) とともに旧定義を解放して 全体を置き換える (doline.f:49-78)。要素の部分上書きとは挙動が違う。
  • 展開は FFS の USE で expnln (expln.f:11-77) が行う: explnstk(idxl, direct) が再帰的に平坦化し、LINE 項目は |mult| 回・向き dir=sign(direct*mult) で再帰、要素項目は |mult| 回積む。反転は要素順を逆にし、各要素インスタンスに ori=.false. を付ける (expln.f:96-123, 51)。要素の値は展開時に定義からコピーされる (tfvcopycmpall)。
  • ori=.false. の BEND では tpara が E1↔E2, AE1↔AE2, FB1↔FB2 を入れ替える (tffs.f:1259-1270)。QUAD/CAVI では FRINGE モードの入れ替え (tffs.f:1322-1325, 1447-1450)。

1.6 MAIN の TRACK / EMIT コマンド (詳細は docs/history/work_main_track.md)

TRACK USE=RING NPART=21 TURNS=1000 NX=(1,10,20) NY=(0) NZ=(1); は initbl.f が icACT として登録 (ActTra.f → track.f → tracka.f)。 キーワードは USE TURNS NPART XEMI YEMI SIGS SIGE ELEC POSI PROTON RADI SPAN CENTER AFTER AXIS SYNC NX NY NZ。 粒子 j の規格化振幅 = (x,px,y,py,z,dp) = (NX[j], 0, NY[j], 0, 0, NZ[j]) (リストは繰り返し、無ければ x=y=1, dp=0)、初期座標 = r·(振幅×(emx,emx,emx,emx,emz,emz)) + codin (r, codin, EMITX/Y/Z, SIGE は直前の EMIT USE=..; が作る古典 SAD の意味)。出力は、追跡前のフラグ一覧、損失の報告、smear の表 (SMEAR ON 既定)、tune (FFT ピーク 8 本) の表、Tracking end:、NX=/NY=/NZ= の確認。 PHSPLOTS=n; の TopDrawer 描画は無視してよい。 K64 版では MAIN の EMIT は何もせず (Use EMIT_TANCE or Emittance[] within FFS.)、TRACK は tinip で SIGSEGV するので SAD で出力を取れない。 pysad は parser.parse_main_commands (ON/OFF, EMIT, NAME=値, TRACK, STOP を順に読む) + FFS.main_exec + maintrack.run_track で古典の意味に実装している (SADScript で同じ手順を書いた版と一致)。

2. 要素型とキーワード

型コード (tfstk.f:277-285): DRIFT=1, BEND=2 (ST も BEND, initb1.f:1004), QUAD=4, SEXT=6, OCT=8, DECA=10, DODECA=12, SOL=20, MULT=22, CAVI=31, TCAV=32, MARK=41, MONI=42, APERT=43, LINE=100。 キーワード名の別名 (initb1.f:729-994): ANGLE, ROT=TILT=ROTATE, DISRAD(RAD), DISFRIN(FRIN), FRINGE(FRMD), ACHROMA(CHRO), RANKICK, ALPHAX=AX, BETAX=BX, PSIX, EMIX=EMITX, SIGZ=SIGMAZ, DROT=DROTATE, K0…K21, SK0…SK21。

3. pysad parser.py の対応

3.1 構成

部品 役割
tokenize / _TOKEN_RE 正規表現トークナイザ。(* *) と !…行末 をコメントとして捨てる。NUMBER は .05 形式も可、IDENT は $ と ` を含む。
_Parser.parse_program → parse_statement → _try_special_form 文ごとに特別形を判定: SetElement[…]、要素型キーワード (_SAD_ELEMENT_TYPES、DECA/DODECA を含む) → _parse_native_element_block、LINE (直後が [ でない) → _parse_line_block、x = BeamLine[…]、Twiss/Emittance/RadiationIntegrals[…]。それ以外は式/代入 (MOMENTUM = 3GEV; → env.set('MOMENTUM', 3e9))。エラーは警告を出して次の ; まで読み飛ばす。
_parse_native_element_block / _parse_sad_params TYPE name=(kw=式 [単位] …) … を読む。;、次の型キーワード、LINE でブロック終了。型名と同じ要素名 (CAVI CAVI=(…)) も可。kw だけで = がなければ True。単位は _SAD_UNITS (§1.2 の initb1.f の単位表: DEG/MRAD/RAD, M/CM/MM, EV/KEV/MEV/GEV, V/KV/MV/GV, HZ/…/GHZ, %, T, GAUSS, JOULE)。env.define_element(name, type, dict)。同じ型で同じ名前を再定義したときは書いたキーワードだけを上書きする (doelem.f と同じ、§1.4)。
_parse_line_block / _parse_beamline_refs_sad LINE name=(…) …;。項目は ID、N*ID → ('REPEAT', N, ID)、-ID → ('REVERSE', ID)、-N*ID は反転 + 繰り返し。
_parse_primary 数値直後の単位 (3GEV, -90 DEG) を掛ける。未知の識別子は文字列として返す。
SADEnvironment _vars (組込み定数+グローバル), _elements {名前: {TYPE, kw: 値}}, _beamlines {名前: 参照列}, _ffs_state (Twiss[]/LINE[] のディスパッチ先)。
SADEnvironment.build_lattice _expand_refs で平坦化 → _build_element → Lattice。最後に周長 C を取り、_harm を持つ空洞に FREQ = HARM·c/C を入れる。
_expand_refs 再帰展開 (深さ 50 まで)。REVERSE は参照列を逆順にし is_reversed を反転して再帰、要素は ('REV_EL', name) にする (二重反転で正順に戻る)。
_build_element / _build_element0 / _apply_extra_params 下表の変換で pysad 要素を作り、_apply_extra_params が DX, DY, K0, F1, FB1, FB2, FRINGE, DROTATE, AE1/AE2 などを属性に渡す (BEND の K0 はファイルで定義しても読まれる = bench_level23h)。数値パラメータ全部を el._raw に残す (FFS の LINE["…"] 表示用, ffscmd.get_value)。QUAD/SEXT/OCT の ROTATE, DX, DY, K0, F1, F2, FRINGE, DISFRIN、CAVI の PHI, DX, DY のうち属性に無いものは _raw のみで、読み込み時の計算には効かず、FFS 側 (ffscmd.set_value, ffs.set_element) で設定した値だけが効く。SAD の既定 (PHI=0, FRINGE=0, DISFRIN=0 など) と一致する限り結果は変わらない。
SADScript / load_sad_file / load_sad_string / load_sad_files 公開 API。load_sad_files(lat, script) は複数ファイルを同じ環境に順に読む (= gs への連結)。.ffs / run_ffs で FFSState に接続。

3.2 _build_element0 の変換 (SAD 値 → pysad 属性)

SAD pysad 変換
DRIFT L Drift(L) そのまま
QUAD L, K1 Quadrupole(L, K1) K1 → K1/L (L>0; pysad の K1 は長さあたり [m⁻²])。K1L キーワードがあればそれを /L。
BEND L, ANGLE, K1, E1, E2, AE1, AE2, ROTATE Bend(L, ANGLE, K1, E1, E2, ROTATE) K1 → K1/L。E1 → E1·ANGLE + AE1, E2 → E2·ANGLE + AE2 (SAD の比→ラジアン、tbende.f:448)。逆向き通過 (REV_EL) では E1↔E2。ROTATE は Bend では設計ロール角 (elements.py Bend.transfer_matrix)。ANGLE=0 でも ROTATE があれば Drift にせず Bend(ANGLE=0, ROTATE=…) のまま保持する (ROTATE 付きの ANGLE=0 の BEND に K0 を与えたとき効かせるため)。SAD では ANGLE=0, K1=0 の BEND は tsteee/tsteer (K0=0 ならドリフト、L=0 なら薄いキック px −= K0) で、ROT は tchge で回す (docs/history/work_rotate.md)。BEND の ROT は Bend.ROTATE (設計ロール)、DROT は DROTATE。FFS の LINE["ROTATE",…] もそれぞれの属性に入る。
SEXT K2 / OCT K3 / DECA K4 Sextupole(K2/L), Octupole(K3/L), Decapole(K4/L) 積分値 → 長さあたり (L=0 ならそのまま)
CAVI VOLT, FREQ, HARM Cavity(VOLT, FREQ) + _harm FREQ=0 かつ HARM>0 なら _harm を記録 → build_lattice で FREQ = HARM·c/C。物理計算 (emit6d.py, track6.py) は _harm と ω0 から SAD と同じ w を作るので β=1 近似の FREQ は使われない。
MONI / MARK Monitor(L), Marker() MARK の Twiss キーワード (BX, AX, EMITX, DP, …) は _raw と env._elements に残り、ffscmd/ffs が参照する。
MULT Multipole(L) _apply_extra_params が K0..K21 を KnL、SK0..SK21 を KsL に、ANGLE・E1・E2・VOLT・FREQ・PHI・HARM・BZ・DVOLT・DPHI・AUTOPHI・CHI2・TAPER を属性に渡す (ANGLE≠0 は docs/19)。
SOL Solenoid(L) BZ・BOUND・GEO・DPX・DPY・DX・DY・DISFRIN・DBZ を属性に渡す。領域の扱いは docs/17。
TCAVI / UND / PHSROT / MAP / COORD / BEAMBEAM TCavity / Undulator / PhsRot / Map / Coord / BeamBeam 数値キーワードを全部 params に入れる (DX 等は誤差の属性にせず変換のパラメータ。_apply_extra_params は何もしない)。PhsRot・Map・Coord・BeamBeam は Marker の派生 (長さ 0)。
不明な型 (SPCH、PROF、TEST など) Drift(L) キーワードは無視 (SPCH・PROF の物理は未翻訳。11/16 に K64 のソースで確認: tturn.f:521 の case (icSPCH) が PSPAC フラグのとき tpspac を呼ぶので SPCH は K64 では物理を持つが pysad は未翻訳。PROF は K64 のソースに現れない)
BEAMBEAM を含むリング (補足) Marker 扱い 11/16 に gs と比較: Twiss のチューン 1e-14、運動量収縮 4e-12 で一致。STURN・COUPLE は K64 のソースでキーワードの登録 (initb1.f) 以外に参照がなく使われない

3.3 既知の制限・SAD との差 (2026-11-16 に確認)

  1. 型が違う再定義: SAD は "already used as …" エラー (§1.4)、pysad は黙って型を変える (DRIFT D1=…; QUAD D1=…; で D1 が QUAD になることを確認)。
  2. MAIN 式の関数 (SIN( ), SQRT( ), ATAN2( ) …) は未対応 (四則と ^ のみ。A=SIN(0.5)+… が警告になることを load_sad_string で確認)。未定義の要素名は SAD が警告するのに対し pysad は黙って飛ばす。
  3. FFS; 以降を同じファイルに含めても USE RING; CELL; CALC; などは読み飛ばされるが、Print[…], LINE["…"], FFS["…"] はその場で評価される。FFS 部は run_sad.py / sadscript.py + ffscmd.py で扱う (docs/history/00_RESUME.md Level 14)。

4. 実例: 3 GeV 20 セルのリング

読み方の例として、3 GeV の 20 セルのリング (周長 603.12 m、3563 要素) のラティスファイル (209 行) を parser で読む。

  • 内容: MOMENTUM = 3GEV; の後に DRIFT/BEND/QUAD/SEXT/OCT/CAVI/MARK/MONI を定義する。式 (L=.413/2、K3=-6000*0.0125、VD=(ROTATE=-90 DEG))、MKS/MKE に Twiss・EMITX・DP を書く、LINE ARCAH … ARCAH2 … ARCA=(ARCAH -ARCAH2) RING=(MKS 20×ARCA + RFC MKE); と反転ライン、LINE の後での BEND/QUAD/SEXT (+DRCT) の 3 回の再定義 (最後が有効。再定義は全キーワードを書いている)、が入っている。
  • 使い方 (番号順):
    1. from pysad.parser import load_sad_file
    2. sc = load_sad_file(<ラティスファイル>)
    3. lat = sc.build_lattice('RING') (要素 3563 個、周長 603.12 m)
    4. 要素の属性 (el.K1 は長さあたり、el._raw['K1'] が SAD の積分値) を見る。
  • 実行ファイルに通す場合は、ラティスファイルと FFS スクリプトを連結して 1 本にして gs に渡す。pysad では python run_sad.py <ラティス> <スクリプト> が同じ連結を行う。
  • ANGLE=0 の VD/HD は §3.2 のとおり Bend のまま保持される。反転ライン -ARCAH2 の中の要素は REV_EL 経由で SAD と同じ順序になる。

検証: 要素数・名前の順序・周長が K64 の LINE[] 出力と一致し、L・ANGLE・K1・K2・K3・E1・ROTATE は K64 の 10 桁出力の丸め (最大 4.9e-11) の範囲で一致、末尾 Twiss は 4e-11 以内。詳細は history/02_lattice_main_validation.md。

BEND の K0 / E1 の FFS 側の意味 (bench_level23): LINE["K0","BPI6.1"]=v は読み出しでは 1 台だけ変わるが、次の CALC / Emittance[] / TrackParticles でファミリー全体が最初の 1 台 (.1) の値に揃えられる (.3 だけ設定した値は CALC 後に消える)。LINE["K0","BPI6"] (ドット無し) や FFS の要素値コマンド BPI6 K0 v はファミリー全体に即座に効く。BPI6.1 K0 v; と書くと SAD は式として評価して何もしない。LINE["E1",name] は ANGLE 比を返す (ANGLE=0 の BEND でもファイルの値)。pysad は ffscmd.FFS.spread_pending、_e_ratio で対応。
