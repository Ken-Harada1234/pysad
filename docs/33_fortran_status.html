33. SAD のソース (ファイル・ルーチン・機能) と pysad の翻訳状況

この文書で分かること: SAD の Fortran ファイルごとに、ルーチン (ファイル:行)・役割・対応する pysad の関数・翻訳の状態・照合の桁 (§1〜§8)、機能別の対応状況 (§9)、pysad のコードに名前が出てこない src のファイル (§10)。 前提: SAD (K64 版) のソース構造 (docs/32)。互換モード (v2 と k64) の意味 (docs/28)。 読む順: §0 の凡例、探したいファイルの節 (§1 追跡、§2 線形光学、…)、機能名から探すなら §9。未対応・未確認の一覧は docs/31。

SAD は K64 版、ソースは <SAD>\src。表の「状態」は、特記がなければ k64 モード (K64 (gs) と同じ動作。gs との照合はこのモード) のもの。v2 モード (既定) で変わった動作は「v2 モード:」と書く (一覧は 28_v2_vs_k64.md)。v2 の値は gs ではなく解析式・独立な数値計算で確かめたもので、gs と比較できないものがある (MEASURE・TRCOD、空間電荷の SPAC、領域内の SOL の要素など)。 「デッドコード・ビルド対象外」の判定は mk/sad.obj.mk の有効リストに無い、または call 0 件のもの。行数の多いデッドコードは節ごとに 1 行にまとめる。 <SAD>\src の *.f 474 本のうち、ファイル名・ルーチン名が pysad/*.py に 1 度も出てこないものの一覧は §10 に付けた (名前の grep だけの確認で、名前を変えて直訳した場合は漏れる)。 根拠: 01_overview.md、27_benchmarks.md、history/00_RESUME.md、history/work_*.md、pysad/*.py の実コード、history/work_unimpl.md、history/v2_changes_*.md。 ルーチンの欄の 名前:数字 は SAD ソースの行番号 (2026-10 時点)。アーキテクチャとコールスタックは docs/32。

10. <SAD>\src の *.f のうち pysad の中に名前が出てこないもの

<SAD>\src\*.f 474 本を grep -w -i で pysad/*.py と突き合わせた (2026-11-16)。名前が出ないだけで、別名のルーチンに直訳されている場合がある (例: tins・tinse は lattice.py の INS の扱い、talign・nalign は ffscmd / lattice のずれ・回転)。 物理計算で名前が出ないもの: qins tins tinse (INS、§2。実装は別名で gs と一致)、qmult qddrif (qtwiss・qdcell 内の別実装に吸収: docs/29 D5)、tfmap tmap (MAP は別名)、 tflifetrack twinit wfbin wfres wiord wjdraw (§1・§8・docs/31 の未翻訳の表。trackb は v2 の measure.py の MEASURE の実装で名前が出るので、この一覧の再現 (2026-11-17) では出ない。名前の再数えはしていない: 要確認)、tbrad tquads tquase tsdrad tserad tstrad tqrad trad trade (Obsolete)、 tconv (追跡の変換は track6 内)、tmuld tmultr (行列の積は numpy)、temitf (EMIT 報告は ffscmd。ファイル名としては出ない)。 それ以外は、旧 MAIN のユーティリティ (pmbump pwrite pundo pkill など)、SADScript のインタプリタ内部 (tfeval1 tfstk tfpart tfsort tfreplace itf* など)、描画 (geodrw phdrw pmbdrw tdplt twsdrw)、ファイル・バッファ (filaux filbuf flmgr getbuf) で、 pysad の方針 (SADScript は Python のインタプリタ、ファイル・描画は Python のライブラリ。36_sadhelp_purpose_policy.md) により翻訳しない。 一覧の再現: for f in <SAD>/src/*.f; do b=$(basename $f .f); grep -q -w -i -- "$b" pysad/*.py || echo $b; done。
