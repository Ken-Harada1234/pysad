27. ベンチマーク一覧 — SAD (K64) と pysad の照合

この文書で分かること: pysad の計算が、SAD の実行系 K64 (gs) と同じ入力でどこまで同じ結果を出すかの一覧 (ベンチマーク) と、回帰・試験の実行方法と最新の通し結果。 前提: pysad は SAD の Fortran を直訳したもので、検証の基準は gs の出力 (参照値) である。この文書は物理の正しさ (解析式との一致) ではなく、gs との一致を主題にする。物理の式と結果の意味は docs/23 と各機能の文書 (docs/07〜11、13〜18) を見る。 読む順: §0 (表の読み方) → §1 方針 → §3 全レベルの一覧 → §5 最新の結果。ベンチの再実行は §2・§4。

最終更新: 2026-11-17 の表 (§3)。§5.1 の試験件数は最新の通し。

0. この表は何を意味するか

  • ベンチ (Level) は、同じ入力 (ラティスとスクリプト) を gs と pysad の両方に与え、出力の数字を突き合わせる検査である。1 つの Level が 1 つの機能 (光学、放射・エミッタンス、追跡、マッチング、スクリプト言語など) を受け持つ。
  • §3 の表の 「現在の結果 (一致度)」 は、gs と pysad の差の最大値である。差は、追跡なら座標の絶対差 (単位は m と rad)、光学・エミッタンスなら相対差で書いてある。例えば「≤5e-11」は、gs が印字する桁 (10 桁、追跡は 5e-11) の範囲で全く同じ値を意味する。差が小さいほど、pysad が gs と同じ計算をしている。
  • 一致の下限は gs の印字の桁 (10 桁) である。それより細かい差は、この比較では見えない。「雑音」と書いた差 (1e-11 以下など) は、gs の側の丸めである。
  • 一致は、特定のラティス・エネルギー・入力での値である。どのラティスでも一致するという保証ではない (§6.1)。
  • 「未照合の項目」の列は、その Level が検査していない機能を示す。「—」は、書くべき未照合の項目が無いという意味である。
  • gs が動かない機能 (K64 の誤りで落ちる、値が NaN になるなど) は、gs との比較ができない。そのときは、解析式や独立な計算との比較を各機能の文書に書いている (K64 の誤りの目録は docs/30、v2 と k64 の違いは docs/28)。

ベンチは <repo>/ の bench_level*.sad (SAD スクリプト) / .result (SAD の出力) / *_pysad.py (pysad の比較スクリプト) / *_run.result (pysad の出力)。 回帰テストの実行スクリプトは run_regression.py (§4)。レベルの階層 (Mainlevel / FFS の構造) は <work-olddocs>/sad_level_structure.md。

場所: すべて <repo>\ (以下「<repo>」)。pysad 本体は <repo>\pysad\。

1. 方針

  • SAD (K64 fork, <SAD>/bin/gs, Ver.1.4.4.2k64) を WSL Ubuntu で実行して参照値 (bench_levelN.result) を取り、 pysad を SAD の Fortran の直訳 として作り、同じ入力で同じ数が出ることを確かめる (再導出はしない)。
  • 一致の目安: 追跡 (TrackParticles) は座標の絶対差 ≤ 1e-9 (SAD の印字精度 1e-10〜5e-11)、オンモメンタムの CALC は 1e-9、 Emittance[] は相対 1e-6、DA は地図 (文字列) と Score の一致。閉軌道・結合・オフモメンタムを経由する CALC は SAD の qcod の緩い収束判定 (conv = min(1e-10, …)) と pysad の数値微分の丸めが入るので相対 1e-7 を目安にする (§3.1)。
  • レベルは「SAD の機能」の階層で、下のレベルから順に一致させる。

2. 実行方法

2.1 SAD (参照値の生成)

wsl -d Ubuntu -- bash -lc 'cd "<repo>" && <SAD>/bin/gs bench_levelN.sad > bench_levelN.result'
  • bench_levelN.sad は ラティス (Mainlevel の素子定義・LINE) と FFS 部 (FFS; 以降の SADScript) を 1 ファイルに連結したもの。 実ラティス (Level 12 以降の 試験用のラティス) では <試験用ラティス>.lat の内容を先頭に貼り、FFS; の後にスクリプトを書く。 SAD の gs は複数ファイルを連結して渡すのと同じ (gs lattice.lat script.sad でもよい) が、リダイレクトで参照を取るときは gs lat script の 2 引数が標準入力待ちで止まるので 1 ファイルに連結する。
  • NPARA=1 を FFS 部の先頭に入れる。 SAD の NPARA の既定値は Packages/init.n で 4 で、TrackParticles は粒子 9 個以上 (npparamin=9) で fork して乱数列が分かれ、また fork した子プロセスが出力を重複して書く。参照値を取るときは NPARA=1 にする (bench_level16g_np1.sad など _np1 が付いたものは NPARA=1 版)。
  • 出力桁数は $FORM="15.10"; (10 桁)。PageWidth = 1999; で折り返しを抑える。Print の出力は Print["TAG ", {...}] の形にして、 結果ファイルの行頭 TAG {...} を pysad の出力と突き合わせる。Level 24 系の参照は WSL の gs を pty 経由 (script -qec) で取る。
  • FFS で使う LINE の先頭要素は MARK でなければならない (tffs.f:2989)。LINE RING=(10*(CELL CELL2)) のような入れ子の繰り返しは構文エラー (LINE CELLP=(CELL CELL2); LINE RING=(10*CELLP); にする)。Do[] などの中で FFS コマンドを使うときは FFS["cell calc;"] で包む (出力ユニットを省略すると表示なし)。
  • SAD (WSL 版) は FITP>1 の GO (bench_level15a) で *** Run time Environment からスクリプトを再実行してしまい 参照値が取れない (NPARA=1 でも同じ)。
  • SAD のクラッシュ (SetElement 周辺の SIGSEGV) に注意: ファイルへのリダイレクトで SetElement[QF,QUAD,K1->0.3] が落ちる。 SAD のバグ・未初期化のためベンチから除いてあるもの: Delete[l,0] (SIGABRT)、Level[..,{-1}]、DeleteCases の第 4 引数、 Insert[l,x,0]、stabz/idim=3 の stab・trace。
  • 誤差は FFS コマンド DELX/DELY/DK/DDK/DTHETA σ 要素 (QD.1 で 1 台、QD* で全台に別々の乱数、SeedRandom[n] で種固定、DUMP で一覧)。 LINE["DX","QD.1"]=v → CALC では 全 QD に展開 される (QD.1 はファミリーの代表)。

2.2 pysad

Windows (Git Bash / PowerShell)、<repo> で:

PYTHONIOENCODING=utf-8 python -u bench_levelN_pysad.py            # Level 1〜12 の比較スクリプト (SAD の値を内蔵/または .result を読む)
PYTHONIOENCODING=utf-8 python -u bench_level12_track_fast.py      # 追跡の numba 版 (track6n)
PYTHONIOENCODING=utf-8 python -u run_sad.py bench_level13a.sad    # SAD スクリプトをそのまま実行 (Level 13 以降)
PYTHONIOENCODING=utf-8 python -u run_sad.py <試験用ラティス>.lat bench_level15a.sad   # ラティスとスクリプトを連結 (SAD の gs と同じ)
PYTHONIOENCODING=utf-8 python -u run_regression.py                # 回帰テスト (全部)。QUICK=1 で遅いものを省略
  • bench_levelN_pysad.py は pysad の API (Lattice, twiss_table, emit6d.emittance6d, track6, match6.Matcher …) を直接呼び、 SAD の値 (スクリプトに埋め込み、または bench_levelN.result から読む) との差を印字する。出力は bench_levelN_pysad.result に保存してある。
  • run_sad.py lattice script は SADScript インタプリタ (pysad/sadscript.py) + FFS コマンド層 (pysad/ffscmd.py) で SAD スクリプトをそのまま実行する。MAIN 部 (素子定義) は parser.py、FFS; 以降は上記。出力は bench_levelN_run.result。
  • 遅いもの: Level 7 (K1≠0 BEND の純 Python 追跡、約 2 分)、bench_level12_track_pysad.py (純 Python、約 1 分)、 run_sad.py bench_level13a.sad (13A-2 の解なしの反復が 3〜4 分)、bench_level16a.sad (DA、numba、数十秒〜)。 run_regression.py は QUICK=1 でこれらを飛ばす。
  • 比較の補助スクリプト: cmp_tags.py (タグ行・ブロックの比較、Level 24)、cmp_lines.py (Print のラベル付き数値行を順に比較)、 cmp_emit_report.py (EMIT 報告の行単位比較)、cmp_radint.py (RADINT 出力ブロック)、cmp_blocks.py --noise 1e-9 (DISP などのブロック比較。 SAD の 1e-17 などの雑音と pysad の 0 は同じ扱い)。マッチングの反復列の比較は NEWTON/Matched/Residual の行だけを抜き出して比べる。

3.1 一致の程度についての注意 (CALC 経路と emit 経路)

  • _num_jacobian (lattice.py) の数値微分の刻みは 1e-7 (K1=0 の BEND の式の分岐境界に 1e-6 が当たるため)。Emittance[] は Level 4 の α_c 8e-10、Level 1 の 6D 値 ≤3e-9。
  • CALC 経路 (閉軌道上の一周行列) は、BEND (ずれなし) の行列を SAD の解析式で組み、結合の式は qmat2twiss の移植を使う。SAD の解析行列は写像の厳密な微分と 2e-8 ずれる (px, py≠0) ので、数値微分で組むと CALC の Twiss が相対 1e-7 程度ずれる。解析式で 3A のチューンは 1.5e-10、3B は全項目 4e-13 以内、14A の DP0 スキャンは SAD と 1e-10。
  • 3C の EX/EPX は 3.2e-11 / 6e-12 で一致 (history/work_emit_report.md)。ずれ・ロール付き BEND の行列は数値微分のまま (history/work_ins_offset.md)。
  • オンモメンタム・閉軌道 0 の CALC (Level 1, 2 の dp=0, 12, 13) は 1e-11 で一致している。

6.1 限界・未確認 (上の表の裏側)

  • 上の一致はどれも、特定のエネルギー・リング (12 セルのリング、小リング、603 m の 3GLS 型 など。試験のラティスごとに異なる) と、試験に固定した入力での値で、一般の入力での一致ではない。

  • POL のスピン追跡は、SOL (BZ≠0) 内の四極のスピンを gs と照合できていない (§6.3)。SOL 領域内の MULT・BEND・CAVI は未対応。Polarization は K64 が NaN を返す (B55)。

6.2 未解決の差 (gs と pysad の食い違い。癖か pysad の不備か未判定)

  1. BEND の F1=0.1 FRINGE=3 を RAD ON で追跡すると gs と合わない (相対 0.7)。DX・DY・ROTATE だけなら 1e-13 で一致。

6.3 保存済みの参照 (bench_level9) と現在の gs の食い違い

  • bench_level9.sad / bench_level9.result (Level 9、SOL BZ=2 T の追跡) は、2026-10-14 に取った gs の出力を保存した参照で、pysad はこれと一致する (回帰 9 は PASS)。
